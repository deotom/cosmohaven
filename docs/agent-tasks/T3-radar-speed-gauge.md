## สเปก
1. **`radarMath.ts` (ฟังก์ชันบริสุทธิ์):** แปลงตำแหน่งโลก → พิกัดเรดาร์ในกรอบของยาน (หมุนตาม `quaternion` ยาน: ด้านหน้ายานชี้ขึ้นบนจอ); ผลลัพธ์ต่อวัตถุ `{ x, y (−1..1 บนจานเรดาร์), height (−1..1 บน-ล่างเทียบยาน), clipped (อยู่นอกระยะ), distance }`; ระยะแสดงผลปรับได้ (ค่าตั้งต้นเสนอ ~ ระยะ HARVEST_SCAN_RANGE ขึ้นไป — ระบุเหตุผล) และวัตถุไกลมากถูกตรึงที่ขอบ (clipped) แทนการหาย
2. **`Radar.tsx`:** วาดด้วย canvas 2D (ไม่ใช่ DOM ต่อวัตถุ) อัปเดต ~10 Hz; จานเรดาร์ + วงแหวนระยะ + ก้านความสูงสั้น ๆ สำหรับวัตถุเหนือ/ใต้ยาน; marker ต่างรูปทรง/สีตามชนิด (ดาวเคราะห์, สถานี, scrap/relic/survey, อุกกาบาต); **เป้าหมายที่ล็อกเน้นพิเศษ**; รูปยานตรงกลาง
3. **มาตรวัดความเร็ว:** วงโค้งรอบเรดาร์ (หรือแถบใต้เรดาร์) แสดง `shipState.velocity.length()` เทียบเพดานความเร็วที่เหมาะสม (ระบุค่าและที่มา) พร้อมตัวเลข u/s
4. **เผื่อที่:** ปล่อยช่อง/ที่ว่างให้ภายหลังใส่ Heat/ศัตรู/สีเขตความปลอดภัย (Phase L) — ยังไม่ต้องทำ แต่โครงสร้าง marker ต้องขยายชนิดได้ง่าย
5. **เลย์เอาต์:** เรดาร์กลางล่าง; แถบปุ่มปัจจุบัน (`hud-bottom-controls`) ต้องไม่ทับเรดาร์ (ย้ายไปไว้ข้าง ๆ/เหนือ หรือย่อ) และข้อความ dock prompt อยู่เหนือเรดาร์; ใช้ได้ทั้งโหมดบินและโหมดอู่ (โหมดอู่แสดงเรดาร์หรือซ่อน — ตัดสินและอธิบายใน log)
6. **ประสิทธิภาพ:** วัตถุหลายร้อยชิ้น (asteroid/scrap) ต้องไม่ทำให้ FPS ตก; ตั้งเพดานจำนวน marker ที่วาด (เช่น เฉพาะที่อยู่ในระยะ + ที่ล็อก)

## **สิ่งที่ตรวจเองไม่ได้**
ความ "ถูกใจ" ของหน้าตา/ขนาด/ความอ่านง่ายของเรดาร์ — ต้องให้ผู้ใช้ดู แนบภาพแล้วบอกตรง ๆ ว่าเป็นข้อเสนอ ไม่ใช่ข้อสรุป

## ข้อควรระวัง
- state เกมอยู่ใน module-level store: อ่านด้วย interval/ref ไม่ใช่ React state 60 fps; การ mutate ทำในฟังก์ชัน module-level (lint ไม่ให้ mutate ใน component)
- ตำแหน่ง/ทิศยานอ่านจาก `shipState` (ซึ่ง Ship เขียนจาก `object.matrix`) — อย่าอ่านจาก `position` ของ object
- อย่าเพิ่ม dependency ใหม่
