# T8 — จำลองวิถีจริงของ autopilot (แรงโน้มถ่วง/ฟิสิกส์) แล้วแก้ให้ไม่ชน

- **ที่มา:** ผู้ใช้ทดสอบเล่นจริงหลัง T1 พบว่า **autopilot ยังชนสิ่งของอยู่ และบางครั้ง "เฉียดดาวแล้วถูกดูดเข้าไป"** (2026-10-04) — T1 ตรวจแค่ geometry เส้นตรง (segment–sphere) ไม่ได้จำลองแรงโน้มถ่วงหรือพลศาสตร์ยาน; log ของ T1 บอกข้อจำกัดนี้ไว้เองและ lead รับงานโดยยังไม่ได้บังคับให้มีการจำลอง
- **Log:** `docs/agent-log/T8-autopilot-sim.md`
- **แทนที่/รวม T6** ได้ (ข้อ "ข้ามเศษที่เข้าไม่ได้" และ benchmark ยังต้องทำ — ดู T6); **ห้ามทำคู่กับ T6 หรือ T7 ถ้าแก้ `autopilot.ts`/`Ship.tsx` ร่วมกัน**

## เป้าหมาย
1. **สร้างตัวจำลองวิถี** ที่ใช้ `runAutopilot` ตัวจริง + แรงโน้มถ่วงจริง + พลศาสตร์ยานที่ใกล้ของจริง เพื่อ **วัด** ว่า autopilot ชนอะไรบ้าง ที่ไหน เพราะอะไร (แทนการเดา)
2. **แก้ autopilot/planner ให้ไม่ชนตามที่วัดได้** — โดยเฉพาะ **แรงโน้มถ่วงดึงยานเข้าดวงที่เฉียดผ่าน**
3. ทำให้ตัวจำลองเป็น **regression test** ถาวร

## สมมติฐานที่ต้องตรวจ (จากโค้ด — ยังไม่ใช่ผลวัด)
- `buildObstacles` ให้ดาวเคราะห์มีรัศมีหลบ = max(รัศมี + บรรยากาศ + 30, **0.55 × wellRadius**) แต่ **แรงโน้มถ่วงเริ่มทำงานที่ 1.0 × wellRadius** (ดู `makePlanet` ใน `sector.ts`: `wellRadius = รัศมี × 3.4`, ดึงที่ขอบ ≈ 0.25 u/s²) — ที่ 0.55 × well แรงดึง ≈ 0.8 u/s² ขณะที่ **แรงขับสูงสุดของ autopilot ≈ 8 u/s²**; ถ้าผ่านด้วยความเร็วต่ำ (เช่น ช่วงเบรกที่ waypoint, หลังออกจากสถานี, tier 3 ที่ "coast" แล้วปล่อยลอย) ระยะตกเข้าหาดาวระหว่างทาง = ½·g·t² ใหญ่มาก → **เส้นทางที่ planner ว่าปลอดภัยจริงๆ ตกเข้าดาว**
- ความเร็วผ่าน waypoint (`WAYPOINT_SPEED = 25`) / ระยะถึง (`WAYPOINT_REACH = 15`) / clearance แอสเทอรอยด์ 10 อาจเล็กเกินสำหรับยานที่เลี้ยวช้า (มีการ overshoot)
- **tier 1 ไม่หลบอุกกาบาตที่เคลื่อนที่** (`avoidMeteors` เฉพาะ tier ≥ 2) — ผู้ใช้อาจเจอ "ชน" ส่วนนี้ด้วย
- **สถานี — ผู้ใช้ยืนยัน (2026-10-04): ชนที่ "หลังสถานี/ขอบสถานี" ตอน tier 1 และ *ไม่ใช่ความตั้งใจ*** (การหลบสถานีเป็นพื้นฐานของทุก tier). สาเหตุที่น่าสงสัยจาก `SpaceStation.tsx`/`station.ts`: planner ใช้ **ทรงกลมเดียวรัศมี `STATION_KEEP_OUT` = 85 ที่จุดกำเนิดของสถานี** แต่ **โครงสร้างจริงยื่นถึงขอบหรือเกินทรงกลมนั้น**: โรงเก็บยาน 18×14×30 (ปากเปิดที่ +Z), **แกน (spine) ยาว 52 ต่อจากท้ายโรงเก็บ ถึง z ≈ −82** (รัศมี 4.2, มี collider 8.4×8.4), ไฟสัญญาณปลายที่ **z ≈ −85**, **แผงโซลาร์บนคานที่ z ≈ −78 กว้าง ±11…±33 → มุมห่างจากจุดกำเนิดราว 89**, วงแหวนที่อยู่อาศัยรัศมี 22 (+ท่อ 2.6) — เส้นทางที่ "แตะผิวทรงกลม" พอดีจึงห่างปลายแกน ~3 หน่วยเท่านั้น และอาจเฉียดแผงโซลาร์ที่ยื่นออกนอกทรงกลม. ยังมีกรณีเริ่มจากในทรงกลม: ตัวดันออกตาม **รัศมีจากจุดกำเนิดสถานี** ซึ่งไม่ใช่ทิศที่ทางออกจริงของโรงเก็บ (+Z)
  - **ให้แก้:** จำลองสถานีเป็น **หลายทรงกลมตามแกนสถานี** (เช่น วงแหวน/โรงเก็บ/แกน/แผงโซลาร์ พร้อม clearance ที่เหมาะสม) แทนทรงกลมเดียว หรือเพิ่มรัศมีให้พ้นส่วนที่ยื่นไกลสุด + margin — ตัดสินด้วยตัวเลขจากตัวจำลอง; **ปากโรงเก็บ (+Z) ต้องยังเข้า/ออกได้** (ทางเข้าสำหรับ DOCK); ดึงขนาดจาก `SpaceStation.tsx`/`station.ts` (ค่าคงที่ `BAY`, `RING_RADIUS`, `SPINE_LENGTH` ฯลฯ) ไม่ฮาร์ดโค้ดซ้ำ — ถ้าค่าเหล่านั้นไม่ถูก export ให้ export (แก้เล็กน้อย)
- **อุกกาบาต — ผู้ใช้ตัดสินแล้ว: ให้การหลบเป็น tier 2 ขึ้นไป (ตามเดิม)** ไม่ต้องเปลี่ยน tier 1 (ให้ตัวจำลองแยกรายงานการชนอุกกาบาตตาม tier)
- ผู้ใช้ไม่ได้ระบุว่า "ชนอะไร ที่ tier ไหน" — **ตัวจำลองต้องจำแนกประเภทการชน** (ดาว/หิน/สถานี/อุกกาบาต) และ tier

## งาน
1. **ตัวจำลอง (ไฟล์ใหม่ เช่น `src/game/autopilotSim.ts` + test):** บูรณาการ (ก) ตำแหน่ง/ความเร็ว: แรงโน้มถ่วงจาก `sampleGravity` + แรงขับตามจมูก + `maneuverAccel`; (ข) ทิศทาง: `angularAccel` ผ่านความเฉื่อยพร้อมการหน่วงที่ใกล้ของจริง; ใช้ค่าจาก `Ship.tsx` (ระบุที่มาของทุกค่าใน log) — **ต้องทำให้เทียบกับของจริงได้**: อย่างน้อยหนึ่งกรณี (เช่น ลอยอิสระรอบดาวหรือเบรกเข้าดาว) ให้เปรียบเทียบวิถีของตัวจำลองกับเกมจริง (เบราว์เซอร์/สคริปต์ในรีโป) แล้วรายงานความต่าง — ถ้าต่างมาก ปรับตัวจำลองก่อนเชื่อผล
2. **ชุดสถานการณ์:** sector จาก seed ≥ 300 ค่า × tier 1–3 × งาน `nav` / `dock` / `harvest`; **รวมเริ่มช้า/นิ่ง** (หลังออกสถานี), ผ่านใกล้ดาว, ผ่านฝูงหิน; ตัวชี้วัด: ระยะใกล้สุดต่อวัตถุทุกชนิด, จำนวนการชน (ระยะ < รัศมี + ครึ่งขนาดยาน), เวลา, ความยาวเส้นทาง
3. **รายงานผลวัดก่อนแก้:** ตาราง "ชนอะไร / tier ไหน / งานไหน / กี่ %" — เพื่อให้รู้ว่าสาเหตุจริงคืออะไร
4. **แก้ตามผลวัด (ทางเลือกที่คาดไว้ — ให้เลือกตามหลักฐาน):**
   - **วางเส้นทางโดยรู้แรงโน้มถ่วง:** ขยายรัศมีหลบของวัตถุที่มีแรงโน้มถ่วงตามความเร็วผ่าน (หรือหลบทั้งหลุมแรงโน้มถ่วงถ้าไม่ใช่ปลายทาง) และ/หรือ **ตรวจเส้นทางด้วยวิถีที่รวมแรงโน้มถ่วง** (forward integration) แล้ววางใหม่ถ้าทำนายว่าชน
   - **จำกัดความเร็วต่ำสุดผ่านหลุมแรงโน้มถ่วง** (ไม่ลอยช้าในหลุม) หรือบังคับเส้นทางออกนอกหลุม
   - ปรับ clearance/`WAYPOINT_*` ตามที่วัด
   - **สถานี:** แก้โมเดลสถานีตามข้างต้น (ข้อนี้ผู้ใช้ยืนยันว่าเป็นปัญหาจริง)
   - อุกกาบาตที่ tier 1: **ไม่ต้องแก้** (ผู้ใช้ยอมรับว่าหลบเป็น tier 2)
5. **ทำให้เป็น regression test:** ชุดย่อยที่เร็ว (รันใน `npm test`) + ชุดเต็มแบบช้า (สคริปต์แยก/skip โดยค่าเริ่มต้น) — เกณฑ์: **ไม่มีการชนดาว/หิน/สถานี** ในชุดสถานการณ์ที่ระบุ ทุก tier

## เกณฑ์ผ่าน (วัดได้)
1. มีรายงาน **ก่อนแก้** (ตารางสาเหตุการชน พร้อมจำนวนตัวอย่าง) และ **หลังแก้** (ตารางเดียวกัน)
2. ตัวจำลองผ่านการเทียบกับเกมจริงอย่างน้อย 1 กรณี (แนบตัวเลขความต่าง)
3. ชุดสถานการณ์ที่ระบุ: **0 การชนดาว/หิน/สถานี** ทุก tier ทุกงาน (ถ้าบางกรณีกำจัดไม่ได้ ต้องรายงานเป็นรายการ พร้อมเหตุผลและวิธีที่เหลือ — ห้ามซ่อน)
4. test เดิมทั้งหมด (รวม 17 test ของ T1) ผ่าน; ความยาวเส้นทางโดยเฉลี่ยไม่เกินเดิมเกิน ~30% (รายงานตัวเลข — การหลบดาวทั้งหลุมย่อมอ้อมมากขึ้น)
5. lint/test/build ผ่าน (ตรวจ exit code build แยก)
6. **ตรวจในเบราว์เซอร์ 1 รอบ** (NAV ไปดาวที่มีหินขวาง + ผ่านเฉียดดาวด้วยความเร็วต่ำ) — headless ช้า ~2 FPS ใช้ polling สถานะ ห้าม sleep สั้น
