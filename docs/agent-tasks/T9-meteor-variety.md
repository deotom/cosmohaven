# T9 — อุกกาบาตหลากหลายและไม่ถี่เกินไป

- **Branch:** `feature/meteor-variety` (จาก master ล่าสุด)
- **ที่มา:** ผู้ใช้ติ (2026-10-04): **อุกกาบาตมาบ่อยไป ดูไม่ random และลูกใหญ่เท่ากันเสมอ เป็นลูกบอลเลย**
- **Log:** `docs/agent-log/T9-meteor-variety.md`
- ทำคู่กับ T2/T3/T7 ได้ (ไฟล์คนละส่วน); **ระวัง T8** ถ้าแก้ `autopilot.ts` (T9 ไม่ควรแตะ autopilot)

## สถานะโค้ดปัจจุบัน (ตรวจแล้ว — `src/game/EventManager.tsx`, `src/game/difficulty.ts`)
- **ถี่:** ช่วงเวลา = สุ่มสม่ำเสมอใน `DIFFICULTY_PROFILES[difficulty].meteorInterval` — Relaxed 30–40 s, **Standard 15–20 s**, Challenging 8–12 s; ลูกแรกที่ 6 s
- **ทุกลูกเหมือนกัน:** `METEOR_RADIUS = 1.3` คงที่, `METEOR_SPEED = 18` คงที่, spin คงที่ `[1.2, 0.8, 0.5]`, `icosahedronGeometry(1.3, 1)` (ลูกบอลเหลี่ยมเล็ก ๆ) สีและ emissive เหมือนกันทุกลูก
- **ทุกลูกเล็งตรงตัวยาน:** เกิดที่ระยะ 80 จากตำแหน่งยาน ทิศสุ่มเกือบสม่ำเสมอ แล้วเล็งไปที่ตำแหน่งยานพอดี → ถ้าไม่หลบจะโดนเสมอ ไม่มี "เฉียด/พลาด"
- ไม่มีการจับกลุ่ม (ฝูง) ไม่มีช่วงเงียบ; ใช้ `Math.random()` (ไม่มี seed)

## เป้าหมาย
อุกกาบาตที่ **มาไม่บ่อย จังหวะไม่สม่ำเสมอ ขนาด/รูปร่าง/ความเร็ว/การหมุนต่างกัน** ดูเป็นก้อนหินจริง ไม่ใช่ลูกบอลเหมือนกันทุกลูก โดยไม่ทำให้ autopilot tier 2 (ที่หลบอุกกาบาต) พัง

## ไฟล์ที่แตะได้
- **ใหม่:** `src/game/meteorField.ts` (ฟังก์ชันบริสุทธิ์: สุ่มช่วงเวลา/ขนาด/ความเร็ว/ทิศ/ฝูง; รับ `rand` เป็นพารามิเตอร์) + `meteorField.test.ts`; `src/game/meteorGeometry.ts` (สร้าง geometry ผิดรูปแบบ seed + แคช) + test
- **แก้ได้:** `src/game/EventManager.tsx`, `src/game/difficulty.ts` (ค่า `meteorInterval` และ/หรือโครงสร้างโปรไฟล์) — ผลกระทบต่อ `difficulty.test.ts` ต้องอัปเดตพร้อมเหตุผล

## สเปก (ค่าเป็นข้อเสนอตั้งต้น — ปรับได้ตามหลักฐานและเหตุผลใน log)
1. **จังหวะ:** ช่วงเวลาระหว่างลูกแบบสุ่มไม่สม่ำเสมอ (เช่น exponential/gamma ตัดต่ำสุด ~15 s) ค่าเฉลี่ย **Standard ≈ 45–60 s** (จาก ~17.5 s), Relaxed ≈ ×2, Challenging ≈ ×0.5; ลูกแรกช้ากว่าเดิม (เช่น 20–40 s); **ฝูง (shower)** ความน่าจะเป็นต่ำ (~10–15% ต่อเหตุการณ์) = 3–6 ก้อนเล็กในช่วงสั้น ๆ จากทิศใกล้เคียงกัน; อนุญาตช่วงเงียบยาวนาน
2. **ขนาด:** การกระจายแบบหางยาว (ก้อนเล็กมาก ก้อนใหญ่น้อย) เช่น รัศมี 0.4–≈4 หน่วย โดยกลางอยู่ราว 0.8–1.2; **มวลตามปริมาตร (∝ r³)** (ค่าปัจจุบัน: รัศมี 1.3 ↔ มวล 40); ก้อนใหญ่ช้ากว่า/เห็นได้ไกล (เพื่อให้หลบได้), ก้อนเล็กเร็วกว่า; ตรวจว่าก้อนใหญ่สุดไม่ "ฆ่ายานในทีเดียว" โดยไม่ยุติธรรม (ดูตรรกะความเสียหายใน `Ship.tsx`: เกณฑ์ชนเร็ว ~12 u/s, บล็อกหลุดเมื่อเสียหาย > 30) — รายงานค่าความเสียหายต่อขนาดใน log
3. **รูปร่าง:** ไม่ใช่ลูกบอล — ผิด/เบี้ยวจาก icosahedron (detail 1–2) ด้วยการเลื่อนจุดยอดแบบ seeded + ยืดไม่เท่ากันตามแกน (± ~40%); **แคช geometry ตามบักเก็ตขนาด/seed** (อย่าสร้างใหม่ทุกลูก — ระวัง GPU churn) และ dispose ตอนหมดอายุ; collider เป็นทรงกลมที่ครอบ (รัศมีไม่เกินภาพจริงเกิน ~10%)
4. **ความหลากหลายอื่น:** ความเร็ว (~10–28 u/s ตามขนาด), การหมุน (ทิศ/ความเร็วสุ่ม 0.2–2 rad/s), สี/emissive ต่างกันเล็กน้อย (หินเทา/น้ำตาล/เหล็ก)
5. **ทิศและการเล็ง:** ไม่เล็งตรงตัวยาก ๆ ทุกลูก — มี **ระยะพลาด (miss distance)** สุ่ม (บางลูกตรง ส่วนใหญ่เฉียด/ผ่านห่าง ~0–30 หน่วย) ทิศเกิดสุ่มทั่วทรงกลม (ปัจจุบันแกน y บีบ ×0.6 — คงไว้ได้ถ้ามีเหตุผล); ระยะเกิด 80–140
6. **เพดานจำนวนที่ active** (เช่น ≤ 12) กันฝูงล้น; อายุขัยเดิม 20 s คงไว้ได้
7. **ห้ามทำให้ autopilot tier 2 พัง:** `meteorTracks` (ตำแหน่ง/ความเร็วจากเมช) ต้องยังทำงาน; มี test/สถานการณ์ว่า `avoidMeteors` ยังตรวจจับก้อนที่เล็ง/พลาดได้
8. ตัวเลือก (ไม่บังคับ): ไม่เกิดขณะจอดที่ dock — ตรวจก่อนว่าปัจจุบันเกิดไหม และรายงาน

## เกณฑ์ผ่าน (วัดได้)
1. test บริสุทธิ์ (ใช้ `mulberry32` เป็น `rand`, ตัวอย่าง ≥ 10,000): ค่าเฉลี่ยช่วงเวลาของแต่ละความยากอยู่ในช่วงเป้า; **ไม่มีช่วงต่ำกว่าค่าต่ำสุดที่ตั้ง**; มีส่วนที่ยาว (ช่วงเงียบ) ตามสัดส่วนที่คาด; สัดส่วนฝูงใกล้เป้า; ขนาด: มัธยฐานเล็ก, สูงสุดไม่เกินเพดาน, ก้อนใหญ่ (> ~2.5) ไม่เกิน ~5–10%; ความเร็วอยู่ในช่วง; ระยะพลาดกระจายตามที่ตั้ง
2. test รูปร่าง: จุดยอดไม่เกินช่วงเลื่อนที่กำหนด; bounding sphere ≤ collider × ~1.1; seed เดียวกัน → รูปเดียวกัน; แคชคืน geometry เดิมสำหรับบักเก็ตเดียวกัน
3. test เดิมผ่านทั้งหมด (รวม `difficulty.test.ts` ที่อัปเดตตามค่าใหม่ พร้อมเหตุผล)
4. **ตรวจในเบราว์เซอร์:** เปิดเกม 3–5 นาที (headless ช้า ~2 FPS — ใช้ polling จำนวน meteor ผ่าน `hazardStats` หรือ debug hook ชั่วคราวที่ **ต้องลบก่อนจบ**) รายงานจำนวนก้อน ขนาด และช่วงเวลาที่สังเกตได้ + ภาพตัวอย่างอย่างน้อย 1 ภาพที่เห็นความต่างของขนาด/รูปร่าง (JPEG เล็ก ≤ ~200 KB)
5. lint/test/build ผ่าน (ตรวจ exit code build แยก); ไม่มี console error

## ตรวจเองไม่ได้ (ต้องเขียนใน log)
ความรู้สึกของจังหวะ ("ถี่/ห่างพอดีไหม"), หน้าตาของก้อนหิน, ความยุติธรรมของก้อนใหญ่ — ผู้ใช้ต้องลองเล่น; ตั้งค่าไว้ปรับได้ที่เดียว (ค่าคงที่/โปรไฟล์) เพื่อจูนง่าย
