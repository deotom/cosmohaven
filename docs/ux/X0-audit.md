## 1. ตัวเลขที่วัดได้

| สถานะ | ข้อความที่เห็นทั้งหน้าจอ (บรรทัด) | แผงที่ทับกันที่ 1280×720 | แผงล้นขอบจอที่ 1280×720 |
|---|---|---|---|
| Build (จอด dock) | 76 | 2 คู่ | ใช่ (แผงขวา) |
| Build + Contracts | 94 | 4 คู่ | ใช่ |
| Build + Trade | 93 | 4 คู่ | ใช่ |

- ที่ **1920×1080 และ 2560×1440 ไม่ทับกัน** ในทุกสถานะที่วัด — ปัญหาการทับเกิดที่จอเล็ก
- แต่ **ความหนาแน่นเท่าเดิมทุกขนาด:** ~75 บรรทัดโชว์ตลอด
- ที่ 1280×720 แผงซ้ายกับขวารวมกัน **กินความกว้างจอ ~65%** (406+427 จาก 1280px) ที่ 1920×1080 ~43% — ฉาก 3D เหลือแค่แถบกลาง

## 2. ของที่แสดงอยู่ตอนนี้ แยกตามความจำเป็น

| กลุ่ม | รายการ (ปัจจุบันแสดงตลอด) | ข้อเสนอ |
|---|---|---|
| **ต้องเห็นตลอด (glance)** | Hull, Credits, ความจุ Cargo, Hunger/Sanity (ย่อ), คำแนะนำ/เป้าหมายปัจจุบัน, เป้าหมายที่ล็อก | แถบ/ไอคอนขนาดเล็ก ≤ ~12 บรรทัดรวม |
| **แสดงตามบริบท** | Auto-Pilot (task, destination, intelligence), Fold Drive (สถานะ/เงื่อนไข), Harvester (ระยะ/ราคา/ไม่มีของในระยะ), ปุ่มอัปเกรด, Contracts, Arrival panel, Dock prompt | โผล่เมื่อเกี่ยวข้อง หรืออยู่ในเมนู `Tab` |
| **ย้ายไปไว้หลัง `?`/H** | รายการปุ่มกด ~30 บรรทัด, ข้อความช่วยเหลือ ("Ships can only be built at a drydock!") | ซ่อนเป็นค่าเริ่มต้น เปิดตอน tutorial และเมื่อกด `?` |
| **ดูเหมือน debug / ตัดหรือย้าย** | "Mass: 1 t", "Thrust used: 0.0 s", "Camera: CHASE · Mouse: STEERING", คำอธิบายระดับ autopilot ยาว ๆ, "Meteors in range: N" | ย้ายไปเมนู/overlay นักพัฒนา หรือยุบเป็นไอคอน |
| **ที่ยังขาด** | **ตัวบอกความเร็ว/คันเร่ง** (ไม่พบในภาพที่ถ่าย), ที่ว่างสำหรับ **Heat/ค่าหัว** (8.12) | ต้องออกแบบเพิ่มที่ว่างไว้ก่อน |

> หมายเหตุ: "Signal Relics: 0/5" แสดงเด่นอยู่ — ตามแผน 8.6 ใหม่ Schematics ต้องเห็นได้ ("n/7") แต่ควรอยู่ใน Codex/เมนู ไม่ใช่บรรทัดบน HUD ตลอดเวลา

## 3. ทางเลือกเลย์เอาต์ (wireframe) — ให้ผู้ใช้เลือก

### ตัวเลือก A — HUD บางที่สุด + เมนู `Tab` (ผมแนะนำ)
```
┌──────────────────────────────────────────────────────────────┐
│ [Hull ▓▓▓▓▓░] [⚡ speed]                    [HC 100] [📦 0/8] │  ← แถบบางด้านบน (2 บรรทัด)
│                                                              │
│                                                              │
│                  (ฉาก 3D เต็มจอ)                              │
│                     ⌖ เป้าหมายที่ล็อก (กรอบเล็ก)               │
│                                                              │
│ (หน้า)(หน้า)                  [ คำแนะนำ: กด E เพื่อ dock ]    │
│ Hunger/Sanity ย่อ                                            │
│ ลูกเรือซ้ายล่าง      [DOCK][CONTRACTS][FOLD][AUTOPILOT]  [?] │  ← แถบการกระทำตามบริบท
└──────────────────────────────────────────────────────────────┘
       Tab = เมนูยานเต็ม: Systems · Cargo · Contracts · Codex · Crew
```
- ข้อดี: ฉากโล่ง ที่ว่างเหลือสำหรับ Heat/ตัวชี้วัดอื่น ใช้ได้ทุกความละเอียด
- ข้อเสีย: รายละเอียด (autopilot, อัปเกรด) ต้องเปิดเมนู — ต้องทำ `Tab` menu ให้ดี

### ตัวเลือก B — แผงด้านข้างแบบพับได้
```
┌──────────────────────────────────────────────────────────────┐
│ [▸ Ship]                                           [Crew ◂] │  ← แผงพับ (ค่าเริ่มต้นย่อ เหลือ 3-4 บรรทัด)
│  Hull ▓▓▓▓░                                    Nova ♥ ✿     │
│  HC 100 · 0/8                                   Hunger ▓▓▓  │
│                                                              │
│                  (ฉาก 3D)                                    │
│                                                              │
│              [DOCK][TRADE][FOLD][PAUSE][VIEW]               │
└──────────────────────────────────────────────────────────────┘
```
- ข้อดี: ใกล้ของเดิมที่สุด แก้ง่ายกว่า A
- ข้อเสีย: รายละเอียดยังอยู่บนจอเมื่อกางออก และยังต้องจัดการการทับกันเอง

### ข้อเสนอของผม: A
เหตุผล: ปัญหาหลักคือ "ปริมาณข้อความ" ไม่ใช่ตำแหน่งแผง — B ยังคงแผงที่ยาวไว้แค่พับได้ ส่วน A ตัดต้นเหตุ และเตรียมที่ว่างให้ระบบที่กำลังจะมา (Heat, ลูกเรือหลายคน, Schematics)

## 4. สิ่งที่ผมต้องการให้ผู้ใช้ตัดสิน (ก่อนเริ่ม X1)
1. **A หรือ B** (หรือผสม)
2. **สไตล์ภาพ:** โทนอุ่น มุมมน ตัวอักษรอ่านง่ายใหญ่ขึ้น (ตรงกับงาน clay — *ผมแนะนำ*) หรือคงสไตล์ sci-fi ใส ๆ แต่ลดข้อความ
3. **ตัวละครลูกเรือบน HUD:** ใช้ "ใบหน้า + ไอคอนอารมณ์" แบบ Animal Crossing (*ผมแนะนำ*) หรือคงแถบ Hunger/Sanity เป็นตัวเลข
4. **Signal Relics/Schematics:** ย้ายออกจาก HUD ไป Codex (*ผมแนะนำ*) หรือคงบรรทัดบน HUD
5. **ปุ่มช่วยเหลือ:** ใช้ `?` หรือ `H` (หรือทั้งคู่)

## 5. ข้อเสนอเกณฑ์วัดหลังแก้ (ต่อ 8.11 ฉ)
- ข้อความที่เห็นตลอดในสถานะบินปกติ ≤ ~12 บรรทัด (วัดจากสคริปต์เดียวกัน)
- **ไม่มีแผนทับกันและไม่ล้นจอ** ที่ 1280×720, 1920×1080, 2560×1440 ทุกสถานะ (สคริปต์เดิมรันซ้ำได้)
- แผง HUD รวมกันกินความกว้างจอ ≤ ~25% ที่ 1920×1080

## 6. ที่ยังไม่ได้วัด (เก็บเป็นงานต่อของ X0)
สถานะ interior view, orbit/ลงจอด (Arrival panel), fold charging, pause menu, start/registration screen, จอแนวตั้ง/มือถือ, ตอนมีหลายลูกเรือ

## 7. ผู้ใช้ตัดสินแล้ว (2026-10-04)
1. **แบบ A** (HUD บางที่สุด + เมนู `Tab` ภายหลัง)
2. **สไตล์: sci-fi ใส ลดข้อความ**
3. **ลูกเรือบน HUD เป็นใบหน้าแบบ Animal Crossing** (ทำใน X3)
4. **ปุ่มช่วยเหลือ: `?`**
5. **Signal Relics:** ผู้ใช้ไม่เข้าใจคำถาม — คำอธิบาย: "Codex" คือหน้าเมนูสมุดบันทึกที่เปิดดูเองได้ (ยังไม่มีในเกม) ตัวเลือกคือ ย้ายบรรทัด "Signal Relics 0/5" ออกจากจอตลอดเวลา หรือคงไว้ — **ค่าเริ่มต้นที่ใช้ตอนนี้:** แสดงบรรทัดนี้เฉพาะเมื่อมี Relic แล้วหรือมี beacon อยู่ใกล้ (แสดงตามบริบท) จนกว่าจะมี Codex/เมนู `Tab`; เปลี่ยนได้
6. **มาตรวัดความเร็ว + เรดาร์ (ผู้ใช้เสนอ):** กลางจอด้านล่าง — รับไว้ในแผน X2 (ดู PLAN 8.11 ค)
