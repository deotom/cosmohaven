## 0. เป้าหมายและแรงบันดาลใจ

ยกระดับจาก "ลูกเรือที่เดินไปกินข้าว/เล่นเกมตู้" เป็น **เกมเลี้ยงชีวิตลูกเรือบนยานแบบ The Sims** ในอวกาศ:

1. **ตัวละครซับซ้อนและมีอารมณ์** — มีความต้องการหลายมิติ อารมณ์ บุคลิก ความสัมพันธ์ และตัดสินใจเองได้
2. **ยานหลักกว้างขวางแบบบ้าน** — มีห้อง/เฟอร์นิเจอร์/สิ่งอำนวยความสะดวกที่ตอบสนองความต้องการ
3. **ยานสำรวจขนาดเล็ก (Scout)** — คล่องตัว ออกไปสำรวจ/เก็บของ แล้วกลับมาเชื่อมกับยานหลัก
4. **สร้างเองหรือใช้ Prebuilt ตามเผ่า (แล้ว customize ต่อได้)** เหมือนสร้างบ้านใน The Sims
5. **ออกแบบเผื่อ Share/Trade ผ่าน Store ในสถานี** (online ใน phase ถัดไป) — *ตอนนี้ออกแบบ data ให้พร้อมเท่านั้น ไม่ implement*

## 2. หลักการออกแบบ

- **Data-driven:** ยาน ห้อง เฟอร์นิเจอร์ ตัวละคร prebuilt ล้วนเป็น JSON ที่ validate ได้ ไม่ฝังในโค้ด
- **แยก "blueprint" ออกจาก "instance":** blueprint = แบบ (แชร์/ซื้อขายได้), instance = ของจริงในเซฟ (มีสถานะ เช่น ความเสียหาย ลูกเรือที่อยู่ข้างใน)
- **ลูกเรือตัดสินใจเองแต่ผู้เล่นสั่งแทรกได้** (priority override) ไม่ต้องคุมทีละก้าว
- **ประสิทธิภาพ:** ลูกเรือหลายคน × ห้องมากต้องคุม cost ของ AI/pathfinding (ดูข้อ 9)
- **คงสไตล์ clay/toon** ของ Animal Crossing ทุกอย่างที่เพิ่ม

## 3. ตัวละคร (Crew 2.0)

### 3.1 Needs (ความต้องการ) — ต่อยอดจากแบบ The Sims

| Need | ตอบสนองด้วย | ผลเมื่อต่ำ |
|---|---|---|
| Hunger | ครัว/ตู้อาหาร/โต๊ะอาหาร | อารมณ์แย่ → ป่วย/ไม่ทำงาน |
| Energy | เตียง/ห้องนอนที่เงียบ | ทำงานช้า, ผิดพลาด |
| Hygiene | ห้องน้ำ/ห้องอาบน้ำ (เผ่าต่างกัน เช่น Jelly ใช้ "ห้องชุ่มชื้น") | ความสัมพันธ์แย่ลง, อารมณ์ลด |
| Fun | Arcade, ห้องนั่งเล่น, ดูดาว, ดนตรี | Sanity ลด |
| Social | คุย/กินข้าว/เล่นด้วยกัน | เหงา, ซึมเศร้า |
| Comfort | เก้าอี้/โซฟา/แสง/อุณหภูมิ | อารมณ์พื้นฐานลด |
| Purpose | ทำงานตามอาชีพ, ภารกิจสำเร็จ | หมดไฟ |
| Species-specific | Floran: แสงอาทิตย์/สวน, Synth: ชาร์จ/ซ่อมบำรุง, Jelly: ความชื้น, Felinian: ที่ซุก/ของเล่น | ตาม trait |

ค่าเดิม Hunger/Sanity ถูกแมปเข้า Hunger และ (Fun+Social+Comfort → Sanity รวม) เพื่อไม่ให้ HUD/ลอจิกเดิมพังตอนย้าย

### 3.2 อารมณ์ (Mood & Emotions)
- **Mood รวม** (−100..100) คำนวณจาก needs + moodlets (เหตุการณ์ชั่วคราว: "กินอาหารอร่อย +10", "นอนบนพื้น −15", "เพื่อนเสียชีวิต −40")
- **อารมณ์ที่แสดงออก** (สุข, ปกติ, เหนื่อย, หงุดหงิด, เศร้า, กลัว, ตื่นเต้น) เชื่อมกับ **ใบหน้า/ท่าทาง/ฟองคำพูด-ไอคอนเหนือหัว**
- เกณฑ์ต่ำสุด = **Breakdown** (ปฏิเสธงาน, ทะเลาะ, เดินเหม่อ, ทำร้ายอุปกรณ์) ผู้เล่นต้องดูแล ไม่ใช่แค่ปล่อยจนตาย

### 3.3 บุคลิกและความสัมพันธ์
- **Traits (2–3 ต่อคน)** เช่น Optimist, Neat freak, Night owl, Glutton, Loner, Brave, Clumsy — ปรับน้ำหนักการตัดสินใจและ moodlets
- **Relationship graph:** คู่ลูกเรือแต่ละคู่มีค่า Friendship/Affinity; ผ่านการคุย กินด้วยกัน เล่นด้วยกัน (สถานะ: คนรู้จัก → เพื่อน → เพื่อนสนิท → คู่รัก/ศัตรู)
- **Likes/Dislikes** (อาหาร กิจกรรม ห้อง) สุ่มจาก pool ตามเผ่า → ให้ผู้เล่น "รู้จัก" ตัวละคร
- **ความตาย/ครอบครัว/เด็ก/วัย:** ตัดสินใจแล้วว่า **มีได้ แต่ปิดได้ทั้งหมด** — ดูหัวข้อ 3.6 (Life Mode)

### 3.4 การตัดสินใจเอง (AI)
แนะนำ **Utility AI** (ไม่ใช่ state machine หรือ behavior tree ล้วน ๆ):

```
ทุก ~0.5–1 วินาที ต่อตัวละคร:
  candidates = กิจกรรมที่ทำได้ตอนนี้ (มีวัตถุ/ห้องว่าง + เข้าถึงได้)
  score(act) = Σ(น้ำหนัก need × ความเร่งด่วน × ความพึงพอใจที่ act ให้)
               × ตัวคูณ trait/mood × ตัวคูณระยะทาง × (1 − จำนวนคนที่รอใช้อยู่)
  เลือกแบบสุ่มถ่วงน้ำหนักจาก top-N (ไม่เลือก max ตรง ๆ เพื่อให้ดูมีชีวิต)
  ผู้เล่นสั่ง "ทำสิ่งนี้" = override priority ชั่วคราว; งานเร่งด่วน (EVAC, ซ่อมยาน) แทรกได้
```

#### 3.4.1 หลักการ "ดูแลตัวเองได้" (Self-care autonomy) — ข้อกำหนดหลัก

เป้าหมาย: **ถ้ายานมีสิ่งอำนวยความสะดวกครบ ลูกเรือต้องอยู่รอดและมีความสุขได้เองโดยผู้เล่นไม่ต้องสั่งสักครั้ง** ผู้เล่นสั่งเพื่อ "จัดการ/เร่ง" ไม่ใช่เพื่อ "ช่วยชีวิต"

| ความสามารถ | พฤติกรรมที่ต้องได้ |
|---|---|
| **มองการณ์ไกล (proactive)** | ไปกิน/นอน/อาบน้ำตั้งแต่ need ลงถึง ~40% ไม่รอจนวิกฤต; มี hysteresis (ทำจนเต็มระดับหนึ่งแล้วค่อยเลิก ไม่สลับกิจกรรมไปมา) |
| **จัดลำดับตามความเร่งด่วนจริง** | วิกฤตเหนือกว่างาน (หิวจัด > ทำงาน); แต่ถ้าเป็นงานฉุกเฉินของยานก็ตัดสินใจชั่งน้ำหนักได้ ไม่ทิ้งงานชีวิต-ความตายเพราะหิวนิดหน่อย |
| **จัดการทรัพยากรเอง (logistics)** | อาหารใกล้หมด → Chef ทำอาหารเตรียม/สั่งผลิต/ปลูกผัก; ของขาด → แจ้งผู้เล่นพร้อมเหตุผล |
| **แก้ปัญหาเมื่อไม่มีของที่ต้องการ** | เตียงไม่พอ → ผลัดกันนอน; ไม่มีห้องน้ำ → ใช้ทางเลือก (ปรับตัวช้า/อารมณ์ลด) แทนการยืนค้าง; เข้าไม่ถึง → หาทางอ้อม/รอ/ขอความช่วยเหลือ |
| **รับมือเหตุฉุกเฉิน** | ไฟไหม้/รั่ว/เสียหาย → อพยพ, ปิดประตู, ซ่อม (Engineer) ตามอาชีพเอง; ใส่ชุดอวกาศเมื่อความดันตก |
| **ดูแลยาน** | ซ่อมของเสียเล็กน้อย เก็บกวาด/ทำความสะอาด รดน้ำสวน เติมเสบียง ตามงานที่ได้รับมอบหมาย |
| **ดูแลกันเอง** | แบ่งอาหาร ปลอบเพื่อนที่เศร้า พาเพื่อนที่ป่วยไปห้องพยาบาล Chef ทำให้คนอื่นกิน |
| **จำและเรียนรู้เบา ๆ** | จำที่ที่ใช้แล้วดี/ไม่ดี ชอบของโปรด เลี่ยงห้องที่เคยมีเหตุ (ผูกกับ likes/dislikes และ moodlets) |
| **รู้ขีดจำกัดตัวเอง** | ป่วย/เหนื่อยจัดจะไม่ฝืนทำงานอันตราย; ใกล้ breakdown จะไปพักเอง |

**กลไกรองรับ**
- **Autonomy level** ตั้งได้: `Full` (ตัดสินใจเองหมด — ค่าเริ่มต้น) · `Guided` (เองแต่ขออนุมัติงานใหญ่) · `Manual` (ผู้เล่นสั่งเอง เหมาะคนที่อยากคุมละเอียด)
- **Safety net:** ถ้ามีทรัพยากรและทางเข้าถึงอยู่ ลูกเรือต้องไม่ตายเพราะ "AI ไม่ทำอะไร" — ตรวจด้วยบั๊กเทสต์ (ดูด้านล่าง); ถ้าไม่มีสิ่งอำนวยความสะดวก **ต้องบอกผู้เล่นว่าขาดอะไร** ไม่เงียบแล้วปล่อยให้ตาย
- **โปร่งใส:** คลิกตัวละครเห็น "กำลังทำอะไร ทำไม" (เช่น "กำลังไปนอน — พลังงาน 28%") และ thought bubble บนหัว เพื่อให้เชื่อได้ว่าฉลาดจริง ไม่ใช่สุ่ม
- **แจ้งเตือนอัจฉริยะ:** รวมปัญหาเป็นรายการสั้น ๆ ("ขาดเตียง 1", "อาหารเหลือ 2 วัน") ไม่เด้งทุกครั้งที่ need ลด
- **ไม่ฉลาดเกินจนเกมน่าเบื่อ:** ยังมีความไม่สมบูรณ์เล็กน้อยตาม traits (Clumsy, Lazy, Glutton) เพื่อให้เป็นเรื่องเล่า แต่ไม่ทำให้ตายเอง

**เกณฑ์ผ่าน (acceptance) ของ Phase C**
1. **Headless soak test:** จำลอง 30 วันเกม ลูกเรือ 4 คน บนยานตัวอย่าง 3 แบบ (starter, prebuilt แต่ละเผ่า, ยานที่ผู้เล่นสร้างแบบสุ่ม) **โดยไม่มี input** → ทุกคนรอด, mood เฉลี่ยไม่ต่ำกว่าเกณฑ์ที่กำหนด, ไม่มีคนค้าง (deadlock/วนซ้ำ) เกิน N วินาที
2. **Fault injection:** ถอดเตียง/ห้องครัว/ปิดทางเดินกลางทาง → ลูกเรือปรับตัวหรือแจ้งปัญหาภายในเวลาที่กำหนด
3. **Emergency drill:** จำลองยานรั่ว/ไฟไหม้ → ลูกเรือทุกคนรอดเมื่อมีทางหนีและอุปกรณ์
4. **Fairness:** ไม่มีคนถูก "ลืม" ตลอด (ไม่แย่งกันใช้ของจนคนหนึ่งอดตลอดไป)

- **Smart objects:** เฟอร์นิเจอร์ประกาศเองว่าให้ need อะไร ใช้เวลาเท่าไร มีช่องใช้กี่คน (ระบบแบบ The Sims) → เพิ่มของใหม่ไม่ต้องแก้ AI
- **Jobs/Roles:** ผู้เล่นมอบหมาย Pilot/Engineer/Chef/Gardener/Medic ฯลฯ — ตัวละครไปประจำที่เมื่อไม่ติด need เร่งด่วน
- **Needs ถูกจำลองแบบ "ลดตามเวลาเกม"** ที่ปรับสปีดได้ (1×/2×/3×) เมื่อเล่นแบบ Sims

### 3.5 ความหลากหลายด้านรูปลักษณ์ (Visual upgrade)
ต่อยอด `Character.tsx` เป็นระบบ **modular parts**:

| ชั้น | ตัวอย่าง |
|---|---|
| ร่าง/สัดส่วน | เผ่าละ 2–3 ทรงตัว, ส่วนสูง/อ้วนผอม slider |
| ใบหน้า | ตา/คิ้ว/จมูก/ปาก/แก้ม หลายแบบ + สีตา |
| ผม/ขน/ส่วนพิเศษเฉพาะเผ่า | ผมมนุษย์, หู/หางแมว, รูปทรงเจลลี่, แผงเซอร์กิตของ Synth, กลีบ/ใบไม้ Floran |
| ชุด | เครื่องแบบตามอาชีพ + ชุดลำลอง + ชุดอวกาศ (สวมอัตโนมัติเมื่อออกนอกยาน) |
| แอ็กเซสซอรี | หมวก แว่น ผ้าพันคอ กระเป๋า ป้ายชื่อ |
| สีสัน | palette ต่อชิ้น (clay material เดิมรองรับสี) |
| อนิเมชัน | นอน, กิน, อาบน้ำ, เล่นเกม, ทำงาน, คุย, ดีใจ, ร้องไห้, หลับในท่าต่าง ๆ, ล้ม |

เทคนิค: สร้างจาก primitive + material เดิม (ไม่ต้องมีโมเดลภายนอก) และเก็บ look เป็น `parts: { slot: partId, color }` เพื่อให้ serialize ได้

### 3.6 Life Mode — ความตาย ครอบครัว และวัย (เปิด/ปิดได้)

**การตัดสินใจ:** ตัวละคร **ตายได้และมีครอบครัวได้** แต่ผู้เล่น **ปิดฟังก์ชันนี้ได้ทั้งหมด** ให้ลูกเรือเป็น **NPC 100%**

| Life Mode | ความหมาย |
|---|---|
| `npc` (Cozy) | ไม่มีความตาย ไม่มีวัย ไม่มีท้อง/เด็ก ไม่มี romance-to-family; ลูกเรือเป็นกลุ่มคงที่ที่ดูแลตัวเองได้ ภาวะวิกฤตทำให้ **ล้มป่วย/หมดสติ/breakdown** แล้วฟื้นได้ |
| `full` (Life) | เปิดครบ: เจ็บป่วยรุนแรง ตาย แก่ชรา ความสัมพันธ์ถึงขั้นคู่ชีวิต ตั้งครรภ์/เกิด เด็กเติบโต ความเศร้าโศก พิธีลา |

> สมมติฐานที่ผมตีความ: "เป็น NPC 100%" = เมื่อปิด ไม่มีกลไกชีวิต-ความตาย-ครอบครัวเลย ตัวละครเป็นลูกเรือถาวรที่ตัดสินใจเองตามข้อ 3.4 ถ้าหมายถึงอย่างอื่น (เช่น ไม่ให้ผู้เล่นควบคุมเลย) ให้แก้ข้อนี้

**หลักสถาปัตยกรรม (สำคัญที่สุด)**
- Life เป็น **โมดูลแยกที่ plug เข้ากับแกน sim** ผ่าน flag `settings.lifeMode` ในเซฟ — แกน (needs/mood/AI/ห้อง/ยาน) **ต้องทำงานครบเมื่อ flag = `npc`** ห้ามพึ่งโมดูล Life
- ทุกระบบที่ Life เพิ่ม (ความตาย, วัย, การตั้งครรภ์, เด็ก, ความเศร้า) ต้องเช็ก flag จุดเดียว (`lifeEnabled()`); เมื่อปิด ไม่ tick ไม่แสดง UI ไม่สร้าง moodlet
- ข้อมูลใน blueprint/CrewBlueprint **ไม่ขึ้นกับ Life Mode** (แชร์ข้ามผู้เล่นที่ตั้งต่างกันได้ — สำคัญต่อ Phase H)

**ความตาย (เมื่อ `full`)**
- **ไม่ตายทันที:** วิกฤต → สถานะ *Critical/Downed* มีช่วงเวลากู้ชีพ (ห้องพยาบาล, Medic, เพื่อนช่วย) → ถ้าไม่ทัน จึงเสียชีวิต
- สาเหตุ: อดอยากรุนแรง/ขาดออกซิเจน/อุบัติเหตุ/ยานเสียหาย/โรค/วัยชรา — ระบบ self-care (3.4.1) ต้องทำให้ **การละเลยไม่ใช่สาเหตุหลัก** ตายต้องมาจากสถานการณ์ที่ผู้เล่น "มีโอกาสแก้"
- ผลตามมา: ความเศร้า (moodlet ต่อคนที่สนิท), ร่างและพิธีลา/อนุสรณ์ (ห้อง Memorial), ข้าวของของผู้ตาย, ที่ว่างบนเตียง/งานที่ต้องหาคนแทน
- **ถ้าตัวละครที่ผู้เล่นคุมตาย (ตัดสินใจแล้ว):** ผู้เล่น **สลับไปคุมลูกเรือคนอื่นหรือทายาท** ได้
  - แสดงรายชื่อผู้สืบทอด: ลูก/คู่ชีวิต/ญาติสาย DNA ที่โตพอ → ลูกเรือคนอื่น
  - ทายาทรับ **ชื่อสกุล/ลำดับรุ่น (generation)** ต่อ; ยานและทรัพย์สินเป็นของ "ครอบครัว/ลูกเรือ" ไม่หายไปกับคนคุม
  - ถ้าไม่มีใครเหลือเลย (ลูกเรือทั้งหมดตาย/ไม่มีผู้โตพอ): เปิด **"ผู้ติดตามคนใหม่"** — สร้างตัวละครใหม่ที่ Haven Drydock หรือรับช่วงยาน (ไม่ใช่ game over ทันที) ส่วนความคืบหน้า (Relic, ยาน, อนุสรณ์ของคนรุ่นก่อน) เก็บไว้
  - ทายาทที่ยังเป็นเด็ก: ผู้เล่นคุมไม่ได้จนโต ระหว่างนั้นสลับไปคุมผู้ใหญ่คนอื่น/ผู้ปกครองแทน
- ความเข้มข้น: ตั้งได้ (`ความถี่อุบัติเหตุ`, `อัตราวัย`, `ปิดความตายจากวัยชราเท่านั้น`)

**ครอบครัว (เมื่อ `full`)**
- ความสัมพันธ์ (3.3) พัฒนาถึง *คู่ชีวิต* ได้ → ตัดสินใจมีลูก (ต้องมีเตียง/ห้องพอ, mood ดี, ผู้เล่นอนุมัติหรือปิด auto ได้)
- ลูกมีช่วงวัย: ทารก → เด็ก → วัยรุ่น → ผู้ใหญ่ → ผู้สูงวัย; **ต้องการต่างกัน** (เล่น/เรียนรู้ ฯลฯ) ทำงาน/ขับยานไม่ได้จนโต
- **ลักษณะที่สืบทอด:** ตามสาย DNA — ดูหัวข้อ 3.6.1 (รวมกรณีลูกต่างเผ่า)
- **การเลี้ยงดู:** มีหลายวิธีและต่างกันตามเผ่า — ดูหัวข้อ 3.6.2
- **อายุขัยต่างกันตามเผ่า** (Synth/Jelly/Floran ต่างจาก Human) เพื่อให้เผ่ามีเอกลักษณ์
- **ขีดจำกัดประชากร:** จำนวนลูกเรือจำกัดด้วยเตียง/ออกซิเจน/อาหาร กันทีมโตจนกระทบ performance (ผูกกับ cap ของข้อ 11.1)

#### 3.6.1 ระบบสาย DNA ที่ซับซ้อน (Genetics & Lineage)

**ตัดสินใจแล้ว:**
- ลักษณะของลูก (รูปร่าง สี นิสัย อายุขัย เผ่า) ตามสาย DNA ของพ่อแม่
- **ลูกต่างเผ่าได้อิสระ ไม่จำกัดคู่เผ่า** (ทุกเผ่าผสมกับทุกเผ่าได้)
- **ใช้ระบบ DNA ที่ซับซ้อน** — รวมถึงผลของการมีลูกกับญาติสายเลือดชิด ไม่ใช้กฎห้ามแบบตายตัว

##### ก. โครงสร้าง Genome

| องค์ประกอบ | แนวคิด |
|---|---|
| **Loci** | ตำแหน่งยีนหลายสิบจุด (ประมาณ 40–80 ในเฟสแรก) นิยามใน `GeneCatalog` (data, มี version) |
| **Alleles** | แต่ละ locus มี 2 alleles (พ่อ 1/แม่ 1) แต่ละ allele มี id และค่า/ผลที่แสดงออก |
| **Linkage groups** | loci จัดเป็นกลุ่ม ("โครโมโซม") สืบทอดเป็นก้อนพร้อม **crossover** แบบสุ่ม — ทำให้ลักษณะบางชุดมักมาด้วยกัน |
| **Dominance** | ต่อ locus: dominant/recessive · incomplete (ผสมกลาง) · codominant (แสดงทั้งคู่) |
| **Polygenic traits** | ลักษณะต่อเนื่อง (ส่วนสูง, อายุขัย, ความทนทาน, แกนอารมณ์) เกิดจากหลาย locus บวกกัน → กระจายแบบระฆังคว่ำ ลูกต่างพี่น้องหลากหลาย |
| **Epistasis (เบา)** | ยีนควบคุมยีนอื่นเป็นชั้น เช่น ยีนเม็ดสีพื้นฐานกำหนดว่ายีนสีผิว/ขนจะแสดงหรือไม่ |
| **Mutation** | โอกาสเล็กน้อยต่อการสืบทอด: allele เปลี่ยนค่า หรือเกิด allele ใหม่ที่อยู่ในกรอบที่ catalog อนุญาต (ลักษณะหายาก/ตัวพิเศษ) |
| **Nature + Nurture** | ลักษณะที่แสดงจริง = ความโน้มเอียงจาก genome × อิทธิพลการเลี้ยงดู (3.6.2) × สภาพแวดล้อม (เช่น แสงสำหรับ Floran) |
| **Seeded RNG** | การเกิดแต่ละครั้งใช้ seed (เก็บในเซฟ) → สร้างซ้ำได้ ทดสอบได้ ไม่เสียหายเมื่อ save/load |

กลุ่มยีน: **Appearance** (ทรงตัว สี ตา ผม/ขน/หู/หาง/ใบ ฯลฯ) · **Temperament** (ความโน้มเอียงของ traits) · **Vitality** (อายุขัย ความทนทาน ต้านโรค) · **Metabolism** (ความเร็วของ needs ตามเผ่า) · **Species modules** (ข้างล่าง) · **Health** (ยีนด้อยเสี่ยง/ยีนต้านทาน)

##### ข. ลูกต่างเผ่าแบบไม่จำกัด — Species Modules & Ancestry

เพื่อให้ผสมได้ทุกคู่โดยไม่ต้องเขียนกฎ/ศิลป์ทีละคู่ ใช้ **species module**:
- แต่ละเผ่ามี **module ยีนเฉพาะเผ่า** (เช่น Floran: ยีนสังเคราะห์แสง/ใบ, Felinian: หู/หาง/ความคล่องตัว, Jelly: ความยืดหยุ่น/โปร่งแสง/ซ่อมตัว, Synth: แผงวงจร/ชาร์จ/ซ่อมบำรุง, Human: ฐาน)
- ลูกรับ allele ของ module จากพ่อแม่ตามปกติ → **ancestry fraction** คำนวณจากสัดส่วน allele แต่ละเผ่า (เช่น 50% Human / 30% Felinian / 20% Floran รุ่นหลาน)
- **trait เฉพาะเผ่า (passive) ปรับความแรงตาม ancestry** — เช่น photosynthesis ของ Floran แรงตามสัดส่วนที่เหลือ; ต่ำกว่าเกณฑ์ = ไม่แสดง
- ชื่อเผ่าที่แสดง = **สร้างอัตโนมัติจากสัดส่วน** (เช่น "Felinian-Human") ไม่ต้องมีเผ่า hybrid ที่ทำมือ
- **Synth:** "DNA" ของ Synth เป็น *core code/โครงสร้างระบบ* ใช้คณิตศาสตร์เดียวกัน แต่ข้อความ/ภาพ/วิธีกำเนิดเป็นเรื่องซอฟต์แวร์และการประกอบ
- **วิธีกำเนิดตามเผ่าของพ่อแม่/แม่แบบ** ยังต่างกัน (3.6.2) การผสมข้ามเผ่าให้ผู้เล่นเลือก "วิธีกำเนิด" ที่พ่อแม่ทั้งสองฝ่ายรองรับ (หรือใช้ห้องพิเศษ ถ้าต้องการ)

> **ความเสี่ยงงานศิลป์ (ต้องทำ spike ก่อน):** ผสมได้ไม่จำกัด = ต้อง **สร้าง appearance จากสูตร ไม่ใช่โมเดลที่ทำมือต่อคู่** แนะนำโครงสร้าง **"กระดูก/ตัวฐานร่วม + ช่องลักษณะ (feature slots) + พารามิเตอร์ morph"** คือทุกเผ่าใช้ rig ตัวละครฐานเดียวกัน ส่วนที่ต่างเป็นชิ้น (หู/หาง/ใบ/แผง), วัสดุ (โปร่งแสง/เมทัลลิก/ขน), สัดส่วน — ผสมกันได้โดยอัตโนมัติ ต้องตรวจก่อนว่า `Character.tsx` ปัจจุบัน (ตัวละครแต่ละเผ่าถูกสร้างแยกกัน) ปรับเป็นแบบนี้ได้ไหม — **ผมยังไม่ได้ตรวจโค้ดส่วนนี้** ควรทำ spike ตอนต้น Phase E

##### ค. สายเลือดชิด (Inbreeding) — จากกลไกพันธุกรรม ไม่ใช่กฎห้าม

- เก็บ **ลำดับวงศ์วาน (lineage graph)** และคำนวณ **inbreeding coefficient (F)** ของเด็กแต่ละคน
- ยีนสุขภาพบางตัวเป็นด้อยและเป็นอันตราย (`deleterious recessive`) — ปกติถูกบังโดย allele ดีของอีกฝ่าย แต่เมื่อ **homozygous** (ได้ทั้งสองข้างเหมือนกัน) จึงแสดงออก ยิ่ง F สูงโอกาสยิ่งสูง
- ผลเป็น **เงื่อนไขสุขภาพ/ลักษณะ** ระดับเบา→ปานกลาง (อ่อนแอ ป่วยง่าย ผลิตภาพต่ำ บางครั้งลักษณะแปลก) ไม่ใช่ความตายทันที
- ตรงข้าม: **ลูกผสมต่างสาย/ต่างเผ่า** ได้ *hybrid vigor* (heterozygosity สูง → Vitality ดีขึ้นเล็กน้อย) — เป็นแรงจูงใจ "วางแผนสายเลือด"
- **ความหลากหลายทางพันธุกรรมของทีม** เป็นค่าที่ผู้เล่นเห็นและจัดการได้ (ต้องรับคนใหม่ผ่าน Crew Hall/ครอบครัวอุปถัมภ์กลับมา ฯลฯ)
- **Gene Counselor** (บริการที่ห้องพยาบาล/สถานี): บอกความเสี่ยงและช่วงลักษณะที่คาดได้ของลูก (เป็นช่วง ไม่ใช่คำตอบแน่นอน) → ทำให้ระบบเป็นการตัดสินใจที่ผู้เล่นใช้ ไม่ใช่แค่เบื้องหลัง
- **ตัวปรับความเข้ม** (settings): `off` · `mild` (ค่าเริ่มต้นแนะนำ) · `realistic` — ผู้เล่นที่ไม่ต้องการเรื่องสุขภาพจากพันธุกรรมปิดได้ ยังได้ลูกที่เหมือนพ่อแม่อยู่
- ใช้ได้เฉพาะ `lifeMode = full` เท่านั้น (ใน `npc` ไม่มีเด็ก/สายเลือดเลย)

##### ง. Lineage, ทายาทและ UI
- เก็บ `parents`, `generation`, `genome`, `ancestry` ใน `CrewInstance`; ต้นไม้ครอบครัว + "เหมือนใคร" + แผงยีนแบบอ่านง่าย (ซ่อนรายละเอียดเทคนิคได้)
- ใช้กับ **ทายาทสืบทอด** (ข้อ 3.6 ตอนผู้เล่นตาย) และอนุสรณ์ของบรรพบุรุษ
- ตัวสร้างตัวละครของผู้เล่นสร้าง genome ที่ให้ลักษณะตรงกับที่เลือก; ตัวละคร prebuilt/จากสถานีมี genome สุ่มจาก pool ของเผ่า

##### จ. ผลต่อสถาปัตยกรรมและขอบเขต
- **`phenotypeFromGenome(genome, rearing, environment) → appearance + traits + stats`** เป็นฟังก์ชันบริสุทธิ์ ทดสอบได้ (ใช้ร่วมกับ Phase E modular parts)
- **GeneCatalog** เป็น data ที่มี version; genome เก็บแค่ allele id → ถ้าเพิ่ม allele ใหม่ ต้องมี migration และ fallback สำหรับ id ที่ไม่รู้จัก
- genome ขนาดเล็ก (ไม่กี่ร้อยไบต์) คำนวณตอนเกิดเท่านั้น แล้ว cache ผลที่แสดงออก — ไม่กระทบ performance รายเฟรม
- **`CrewBlueprint` ที่แชร์ได้เก็บแค่ appearance + traits ไม่เก็บ genome** (กันการซื้อขาย/ฟาร์มสายเลือด; ทบทวนใน Phase H)

##### ฉ. การทดสอบ (acceptance)
1. **Mendelian check:** จำลองคู่พ่อแม่หลายหมื่นครั้ง สัดส่วน dominant/recessive ใกล้ค่าทฤษฎี; linkage/crossover กระจายถูกต้อง
2. **Determinism:** seed เดียวกัน → ลูกเหมือนเดิมทุกครั้ง, save/load แล้วไม่เปลี่ยน
3. **Fuzz ทุกคู่เผ่า:** สุ่มคู่ผสมทุกคู่ (รวมข้ามเผ่าหลายรุ่น) อย่างน้อยหลายพันครั้งต่อคู่ → `phenotypeFromGenome` ต้องให้ผลที่ **เรนเดอร์ได้ไม่พัง** (ไม่มีชิ้นทับ/ว่างเปล่า/ค่าเกินช่วง)
4. **Inbreeding:** F คำนวณตรงกับ lineage ตัวอย่าง; ลูกจากคู่สายเลือดชิดมีเงื่อนไขสุขภาพถี่ขึ้นตามคาด แต่ **ไม่มี outcome ที่ทำให้ตัวละครเล่นไม่ได้/ติดสถานะค้าง**
5. **ประชากร:** หลายรุ่น (เช่น 10 รุ่นเร่งเวลา) ไม่ทำให้จำนวน/หน่วยความจำ/เวลาคำนวณระเบิด และไม่มีเด็กไร้ผู้ดูแลค้างระบบ

#### 3.6.2 การเลี้ยงดูเด็ก (Child-rearing) — ต่างกันตามเผ่า

**เด็กโตต่อแม้สลับโหมด `full`→`npc` (ตัดสินใจแล้ว):** วัยยังดำเนินต่อสำหรับเด็กที่เกิดแล้วจนโตเป็นผู้ใหญ่ แล้วจึงหยุดวัยตามโหมด npc (ไม่มีเด็กเกิดใหม่)

**ทางเลือกการเลี้ยง 5 แบบ** (ผู้เล่นเลือกต่อเด็ก เปลี่ยนได้):

| ทางเลือก | อธิบาย | ผลต่อเด็ก | ต้นทุน/ข้อควรระวัง |
|---|---|---|---|
| **1. ผู้ปกครอง/ลูกเรือเลี้ยงเอง** | พ่อแม่หรือลูกเรือคนอื่นดูแลในยาน | ผูกพันสูง (bonding) นิสัยได้อิทธิพลจากผู้เลี้ยง | กินเวลาผู้ใหญ่ (กระทบงาน) |
| **2. ใช้ระบบของยาน (Nursery)** | ห้องเด็ก/ระบบอัตโนมัติ/หุ่นดูแล | ปลอดภัย พัฒนาตามมาตรฐาน ผูกพันต่ำ ทักษะพื้นฐานดี | ใช้พลังงาน/Scrap, ต้องมีห้อง Nursery |
| **3. จ้างพี่เลี้ยง** | จ้าง NPC จากสถานีมาประจำยาน | คุณภาพขึ้นกับพี่เลี้ยง (traits/สกิล) | เงินเดือนต่อเนื่อง, ใช้เตียง/พื้นที่ |
| **4. ฝากสถานีอวกาศ** | Station Daycare / โรงเรียนประจำ ที่ Haven Drydock | เด็กเติบโตที่สถานี ได้ทักษะหลากหลาย; ผู้เล่นเยี่ยมได้เมื่อแวะ; ผูกพันลดลงตามเวลาที่ห่าง | ค่าฝากรายรอบ, ต้องกลับไปสถานีเพื่อเยี่ยม |
| **5. มอบให้ครอบครัวอุปถัมภ์ (Adoption)** | ยกให้ครอบครัวที่สถานีเลี้ยงต่อถาวร | เด็กออกจากทีม; อาจกลับมาพบเป็นผู้ใหญ่ (เหตุการณ์พิเศษ) | **ไม่มีเงินไหลมาหาผู้เล่น** — ดูหมายเหตุ |

> **ยืนยันแล้ว:** ข้อ 5 เป็น "มอบให้ครอบครัวอุปถัมภ์" (ไม่มีค่าตอบแทนให้ผู้เล่น ไม่มีการซื้อขาย) เพราะเด็กต้องไม่เป็นสินค้า ทั้งเพื่อโทนอบอุ่นของเกมและเพื่อไม่ให้เป็นปัญหาตอนมี Store ออนไลน์
> **กฎถาวร:** เด็กและตัวละครที่มีชีวิต **ห้ามเป็นสินค้า/ห้ามถูกซื้อขายด้วยสกุลเงินใน Store** — แชร์ได้เฉพาะ appearance blueprint (ดู 10.3)

**ความต่างตามเผ่า (ข้อเสนอเริ่มต้น แก้ได้):**

| เผ่า | กำเนิด | การเลี้ยง/การเติบโต |
|---|---|---|
| Human | ตั้งครรภ์/คลอด | ช่วงเด็กยาว ต้องการความใส่ใจสูง เรียนรู้จากผู้ใหญ่ ผูกพันมีผลมาก |
| Felinian | ครอกละ 1–3 ตัว | โตเร็ว ซุกซน เน้นเล่น/สังคม ใช้ที่ซุก/ของเล่น |
| Jelly | แตกตัว (budding) จากพ่อแม่ | โตเร็ว ใช้อ่างสารอาหาร/ห้องชุ่มชื้น เรียนรู้เก็บ "ความทรงจำ" บางส่วนจากพ่อแม่ |
| Synth | ประกอบ/สร้างหน่วยใหม่ (ต้องใช้ชิ้นส่วน/Scrap) | "การเลี้ยง" คือ *การฝึก/อัปโหลดโปรแกรม* ใช้ห้องแล็บ/เวิร์กช็อป; "ยีน" = ซอฟต์แวร์/โครงสร้างที่สืบทอด |
| Floran | เมล็ดปลูกในสวน/ห้องแสง | ต้องการแสง/ดิน/น้ำ โตช้าเป็นช่วง ๆ ตามฤดู/แสง; ผูกกับสวนไฮโดรโพนิกส์ |

- แต่ละเผ่ามี **ชุดทางเลือกการเลี้ยงที่เหมาะต่างกัน** (เช่น Jelly เหมาะกับ Nursery แบบอ่าง, Synth เหมาะกับห้องแล็บ/พี่เลี้ยงเป็นวิศวกร)
- การเลี้ยงมีผลต่อ **traits ที่แสดงออก** (genome ให้ความโน้มเอียง การเลี้ยงดูกำหนดผลลัพธ์)
- เด็กมี **ช่วงวัยและความต้องการต่างจากผู้ใหญ่** (เล่น/เรียนรู้/ความปลอดภัย) และใช้ smart objects ของตัวเอง (เปล, ของเล่น, โต๊ะเรียน)
- เมื่อโตเป็นผู้ใหญ่ เด็กเลือกอาชีพตาม traits/สกิลที่ได้สะสม และกลายเป็นลูกเรือ/ทายาทได้

**การเปลี่ยนโหมดระหว่างเล่น**
- `npc` → `full`: อนุญาต ตัวละครเริ่มมีวัยจากตอนนั้น (ไม่ย้อนหลัง)
- `full` → `npc`: อนุญาต หยุดความตาย/การตั้งครรภ์/เด็กเกิดใหม่ทันที; คนที่เสียไปแล้วยังอยู่ใน "อนุสรณ์"; **เด็กที่เกิดแล้วโตต่อจนเป็นผู้ใหญ่** (ตัดสินใจแล้ว) แล้วจึงหยุดวัย; การเลี้ยงดู (3.6.2) ที่กำลังดำเนินอยู่ทำงานต่อจนเด็กโต
- **ค่าเริ่มต้น (ตัดสินใจแล้ว):** `npc` — เปิด `full` ได้จากหน้าตั้งค่าตอนเริ่มเกมและในเมนู

**เกณฑ์ผ่าน**
1. **ปิด Life:** soak test 30 วัน (ข้อ 3.4.1) ผ่านโดยไม่มีเหตุการณ์ตาย/วัย/เด็กเกิดเลย และไม่มี UI ของฟีเจอร์เหล่านี้โผล่
2. **เปิด Life:** soak test เดียวกัน + อายุขัยที่เร่ง → ทดสอบว่าไม่เกิดสถานะผิดปกติ (เด็กไม่มีผู้ดูแล, เตียงเกิน cap, ผู้เล่นไม่มีตัวละครแต่ยังเล่นต่อ)
3. **สลับโหมด** ทั้งสองทิศทางโดย save/load แล้ว state ถูกต้อง
4. blueprint/แชร์ที่สร้างในโหมดหนึ่งโหลดในอีกโหมดได้ปกติ

### 3.7 การได้ตัวลูกเรือ
- เริ่มด้วยตัวที่ผู้เล่นสร้าง 1 คน (เหมือนปัจจุบัน) + **สถานีมีบริการ "Crew Hall"**: จ้าง/รับสมัครลูกเรือสุ่มที่มี traits ต่างกัน (ใช้ Scrap หรือสกุลเงินใหม่)
- ผู้เล่นสร้างลูกเรือเองเพิ่มได้ (ตัวสร้างเดียวกัน)
- ขนาดทีมเริ่มต้นแนะนำ **1–4 คน** (ขีดบนที่สัมพันธ์กับจำนวนเตียง) เพื่อคุม performance และ UX

## 4. ยานหลัก (Mothership) — จากบล็อกสู่ "บ้าน"

### 4.1 โมเดลการสร้างใหม่
เปลี่ยนจาก "บล็อก 3D ติดกัน" เป็น **โมดูลห้อง + เฟอร์นิเจอร์** แบบ The Sims:

1. **Hull/Frame** — โครงภายนอกเป็นกริด (ใช้ระบบกริดเดิมต่อยอด)
2. **Rooms** — ลากพื้นที่กำหนดห้อง เติมพื้น/ผนัง/ประตู/ช่อง airlock
3. **Furniture & Facilities** — วางวัตถุในห้อง (หมุน/ย้าย/ขายคืนได้)
4. **Systems** — เครื่องยนต์, พลังงาน, ออกซิเจน, แรงโน้มถ่วงเทียม ฯลฯ ที่ห้องเหล่านี้ต้องการ
5. **Exterior parts** — เสาอากาศ, แผงโซลาร์, ท่อไอเสีย, ท่า dock ของยานสำรวจ

### 4.2 สิ่งอำนวยความสะดวก (ชุดเริ่มต้นที่เสนอ)

| หมวด | วัตถุ/ห้อง | ตอบ need |
|---|---|---|
| อาหาร | ตู้อาหาร (มีอยู่), ครัว+เตา, โต๊ะอาหาร, สวนไฮโดรโพนิกส์ | Hunger, Social |
| พัก | เตียงเดี่ยว/คู่, ห้องนอน, เบาะพัก | Energy, Comfort |
| สุขอนามัย | ห้องน้ำ, ฝักบัว/ห้องอาบ, เครื่องซักผ้า | Hygiene |
| สันทนาการ | Arcade (มีอยู่), โซฟา+จอ, ห้องดนตรี, หอดูดาว, ห้องออกกำลังกาย | Fun, Social |
| งาน | ห้องควบคุม/บริดจ์ (Pilot), เวิร์กช็อป (Engineer), ห้องแล็บ, ห้องพยาบาล | Purpose |
| ระบบยาน | เครื่องยนต์, เครื่องกำเนิดพลังงาน, ถังออกซิเจน, Hangar | Mechanics |
| ตกแต่ง | ต้นไม้ รูปภาพ พรม ไฟประดับ โปสเตอร์ | Comfort/Mood |
| เฉพาะเผ่า | สวนแสง (Floran), แท่นชาร์จ (Synth), อ่างเจลลี่ (Jelly), ที่ปีนเล่น (Felinian) | Species need |

แต่ละชิ้นมีค่า: ขนาด, ราคา (Scrap), ผลต่อ need, ช่องใช้งาน, ค่า "ความสวยงาม" (ส่งผลต่อ mood ห้อง), การใช้พลังงาน

### 4.3 "ความกว้างขวางแบบยานอวกาศ"
- ยานมีขนาดตั้งแต่ **Starter (เล็ก 6–10 ห้อง)** ถึง **Large (หลายชั้น)** ขยายได้ที่ drydock เพิ่ม **ชั้น (deck)**
- ทางเดิน/ลิฟต์/บันได เชื่อมชั้น; pathfinding รองรับหลาย deck
- มุมมอง **cutaway** (ตัดชั้นบนออกดูภายใน — เหมือน The Sims ซ่อนผนัง) ต่อยอดจาก interior view `V`
- ต้องมีกฎการอยู่อาศัยพื้นฐาน: แรงโน้มถ่วงเทียม, ออกซิเจน, พลังงาน — ห้องที่ขาดจะมีผลกับ mood/สุขภาพ (**ทำแบบเบาก่อน** แล้วค่อยลึก)
- ข้อจำกัดที่ต้องออกแบบ: ยานใหญ่ = มวล/ความเฉื่อยมาก → ฟิสิกส์บิน (compound body ที่มีอยู่) ต้อง **ทำให้ห้อง/เฟอร์นิเจอร์ไม่สร้าง collider ทีละชิ้น** (ใช้ collider ของ hull ภายนอกเท่านั้น; ภายในเป็นกริดสำหรับ pathfinding)

### 4.4 โหมดสร้าง (Build UX)
- ที่ drydock เท่านั้น (กฎเดิม) แต่เพิ่ม **"Home Edit Mode"** ที่วางเฟอร์นิเจอร์ได้เมื่อ dock/จอดสงบ
- Tools: Hull, Room paint, Wall/Door, Furniture, Eyedropper, Undo/Redo, Sell/Move, Blueprint save
- งบประมาณ Scrap ชัดเจน; ปรับของตกแต่งฟรี/ถูกเพื่อให้ผู้เล่นกล้าลอง
- Validation แบบเรียลไทม์: ห้องต้องมีทางเข้า, ต้องมีเตียงอย่างน้อยเท่าลูกเรือ, ต้องมีเครื่องยนต์/พลังงาน — แสดงเตือนแทนการห้ามสร้าง

### 4.5 AI ของยานแม่ (Ship AI) และระบบพลังงาน

**ข้อเสนอที่แนะนำ: ดี — ผูก "ความฉลาดของ AI" กับ "พลังงานที่มี" แบบลดระดับอย่างนุ่มนวล (graceful degradation) ไม่ใช่พังทันที** เพราะทำให้ได้ทั้งความซับซ้อน การตัดสินใจ (อัปเกรด AI คุ้มไหมเมื่อกินไฟ) และไม่ทำให้เกมน่าหงุดหงิด

**แนวคิด:** ยานแม่มี AI ที่ผู้เล่นเริ่มต้นได้แค่ระดับช่วยงานพื้นฐาน แล้วอัปเกรดเป็นผู้ช่วยที่ฉลาดมาก (ต่อยอดและรวมแนวคิด Autopilot tier ที่เล่นอยู่ตอนนี้เข้าเป็นส่วนหนึ่ง)

| ระดับ | ความสามารถ | ไฟที่ใช้ |
|---|---|---|
| **0 Basic (เริ่มต้น)** | ช่วยงานพื้นฐาน: แจ้งเตือน, บินตามจุด, ปิด/เปิดระบบพื้นฐาน, สรุปสถานะยาน | ต่ำ |
| **1 Assistant** | จัดการเสบียง/ตารางงานให้ลูกเรือแนะนำ, **จัดลำดับการใช้ไฟอัตโนมัติ**, ซ่อมแซมเล็กน้อยด้วยโดรนบนยาน | ปานกลาง |
| **2 Advisor** | ทำนายปัญหาล่วงหน้า (ไฟจะไม่พอ/เสบียงหมด/ความเสี่ยงเหตุการณ์), วางแผนเส้นทาง/Fold, **สั่งงานฝูงยานสำรวจ** (หัวข้อ 5.1) | สูง |
| **3 Command** | ตัดสินใจเชิงกลยุทธ์แทนได้ภายใต้นโยบายที่ผู้เล่นตั้ง, เจรจา/ประมูลที่สถานี, ปรับปรุงภาพรวมทั้งทีมและยาน | สูงมาก |

**ผู้เล่นตั้ง "ระดับการมอบอำนาจ" แยกตามด้าน** (ยาน/พลังงาน/ลูกเรือ/ฝูงยาน/การค้า) เช่น `แนะนำอย่างเดียว` · `ทำเองแต่แจ้ง` · `ทำเองเงียบ ๆ` — AI ฉลาดแค่ไหนก็ไม่ลดบทบาทผู้เล่นถ้าเลือกคุมเอง (เชื่อมกับ Autonomy level ของลูกเรือใน 3.4.1)

##### ระบบพลังงาน (Power budget)
- **แหล่งผลิต:** แผงโซลาร์ (แรงตามระยะจากดาวฤกษ์/อยู่ในเงา → ต่างกันตาม sector), เครื่องปฏิกรณ์ (ใช้เชื้อเพลิง), แบตเตอรี่ (สำรอง)
- **ผู้ใช้ไฟมีระดับความสำคัญ:**
  1. **Critical** — ออกซิเจน/ความดัน, ความแข็งแรงตัวยาน, **AI ขั้นต่ำ** (ไม่ถูกตัดก่อนหมวดอื่น)
  2. **Essential** — เครื่องยนต์, ไฟส่องสว่าง, ครัว/ห้องนอน, ห้องพยาบาล
  3. **Comfort** — Arcade, ห้องนั่งเล่น, ห้องดนตรี
  4. **Optional** — โหมดประสิทธิภาพสูงของ AI, ระบบปรับแต่งต่าง ๆ
- **ไฟไม่พอ = ลดระดับตามลำดับ ไม่ใช่ดับทั้งยาน:** ตัดหมวดล่างก่อน; **AI จัดการเองตามระดับ** (Basic ทำไม่ได้ ต้องให้ผู้เล่นตัดเอง, ระดับ 1+ ตัดอัตโนมัติอย่างฉลาด)
- **AI ลดความฉลาดตามไฟที่มี ("compute budget"):** ไฟขาด AI ถูกลดลงเป็นระดับต่ำชั่วคราว → ความสามารถขั้นสูงหาย, ต้องทำเอง ไม่ใช่ระบบพัง

##### ทำไมมันดี และต้องระวังอะไร
**ดี:** ทำให้ "อัปเกรด AI" ไม่ใช่การกดซื้อแล้วจบ ต้องวางแผนพลังงานคู่กัน; เชื่อมกับ sector (ที่ไกลจากดาว โซลาร์อ่อน), กับเผ่า (Floran ต้องแสง, Synth ต้องชาร์จ), กับห้อง (ห้องมืดอารมณ์ลด), กับแรงตึงเครียด (8.1)

**ความเสี่ยงที่ต้องกันไว้:**
- **วงจรมรณะ (death spiral):** ไฟขาด → AI โง่ลง → จัดการไฟแย่ลง → ไฟขาดหนักขึ้น — ต้องมี **Safe Mode** อัตโนมัติ (ตัดทุกอย่างยกเว้น Critical + เปิดไฟสำรอง/สัญญาณ SOS) และทางออกที่ผู้เล่นทำเองได้เสมอ
- **ผู้เล่นไม่เข้าใจว่าทำไม:** ต้องมีหน้า Power ที่อ่านง่าย (ใครใช้เท่าไหร่ ใครถูกตัดเพราะอะไร) และคำเตือนล่วงหน้า (ดู UI 8.2)
- **อัปเกรดได้แต่ไม่คุ้ม:** ปรับ balance ให้ทุกระดับมีสถานการณ์ที่คุ้มกว่า
- **AI ทำให้เกมเล่นเองจนไม่ต้องทำอะไร:** ใช้การมอบอำนาจแยกด้านและความเสี่ยงของเหตุการณ์ (8.1) ถ่วงดุล
- ใน `lifeMode = npc` ไฟขาด **ไม่ทำให้ใครตายหรือบาดเจ็บถาวร** เพียงลด mood/ความสามารถ; ใน `full` อาจทำให้เข้าสถานะ Critical ได้หากละเลยเกินไป

**เชื่อมกับระบบอื่น:**
- **ฝูงยาน (5.1):** ระดับ AI ของยานแม่กำหนดความสามารถสูงสุดและจำนวนยานสำรวจที่สั่งงานพร้อมกัน; AI Core ของยานสำรวจเป็น "ลูกน้อง" ที่ได้ประสิทธิภาพเพิ่มจากยานแม่
- **Autopilot ปัจจุบัน** (Basic/Advanced/Expert ที่ `U`/`I` อัปเกรด): ย้ายเข้าเป็น "งานนำทาง" ของ Ship AI ไม่ทำซ้ำสองระบบ
- **ลูกเรือ (3.4.1):** AI ระดับสูงช่วยจัดตารางงาน/เตือนความเสี่ยง แต่ลูกเรือยังตัดสินใจดูแลตัวเองได้โดยไม่ต้องพึ่ง AI (ไม่ใช่จุดล้มเหลวเดียว)
- **ข้อมูล:** `ShipBlueprint.power = { generators, storage }` และ `ai = { tier }` คำนวณซ้ำฝั่งผู้รับ ไม่เชื่อค่าในไฟล์ที่แชร์

## 5. ยานสำรวจ (Scout / Explorer Craft)

| หัวข้อ | แนวทาง |
|---|---|
| แนวคิด | ยานเล็ก 1–2 ที่นั่ง "พอดีตัว" คล่องแคล่ว ใช้เก็บ Scrap/Relic, สำรวจดาว, ลงดาวง่ายกว่ายานแม่ |
| การปล่อย/รับ | ออกจาก **Hangar bay** ของยานแม่ (ต้องมีห้อง Hangar); กลับมาเชื่อมเพื่อเติมเชื้อเพลิง/ถ่ายของ |
| การควบคุม | ใช้ระบบบินเดิม (6-DOF) แต่ **มวลน้อย แรงเร่งสูง ความเร็วสูงสุด/พิสัยต่ำ**; ยานแม่ถูก "ทอดสมอ" หรือโคจรอยู่ (autopilot task HOLD/ORBIT) |
| ใครขับ | มีคนขับ (ผู้เล่น/ลูกเรือที่ assign, skill ให้โบนัส) · ไร้คนขับ (Remote หรือ Autonomous ด้วย AI Core) · ขึ้นกับชิ้นส่วนของยาน — ดู 5.1 |
| ภารกิจ | สำรวจ/เก็บของ/ลงดาวผิวเล็ก/ตามหา Relic ไกลจากยานแม่; ความเสี่ยง: ออกไกลเกินพิสัย = เชื้อเพลิงหมด/ต้องกู้ภัย |
| การสร้าง | ใช้ **ระบบ builder เดียวกัน** (frame + parts + cockpit) แต่ห้องภายในเป็น "ห้องนักบิน/ที่เก็บของ" ไม่ใช่ห้องอยู่อาศัย |
| Prebuilt | Scout ต่อเผ่า (เช่น Felinian: เร็วและเล็ก, Synth: ทนทาน, Jelly: ยืดหยุ่น) |
| ข้อควรระวัง | gravity/dock/arrival/autopilot ปัจจุบันผูกกับ "ยานลำเดียว" (`shipState`) ต้อง refactor ให้ **ควบคุมยานที่ active** ได้ (ดู Phase B) |

### 5.1 ยานสำรวจแบบมีคนขับ / ไร้คนขับ / สั่งงานอัตโนมัติ

**ตัดสินใจแล้ว:** ยานเล็ก **ไม่จำเป็นต้องมีคนขับ** — ปล่อยให้บินเอง (auto) ตามงานที่ผู้เล่น assign ได้ ขึ้นกับยานที่ซื้อหรือสร้างเอง (ชิ้นส่วนบนยานกำหนดว่าขับได้แบบไหน)

| โหมดควบคุม | ใครขับ | ต้องมีอะไรบนยาน | เหมาะกับ |
|---|---|---|---|
| **Manned** | ผู้เล่น หรือลูกเรือที่ assign เป็นนักบิน | ที่นั่งนักบิน (Cockpit) | งานที่ต้องการการตัดสินใจ/ลงดาว/สำรวจละเอียด; ลูกเรือเก่งให้โบนัส |
| **Remote** | ผู้เล่นบินผ่านกล้องของยาน (ตัวละครยังอยู่ยานแม่) | Remote link + ยานอยู่ในระยะสัญญาณ | เสี่ยงอันตรายโดยไม่เสี่ยงคน; ผู้เล่นยังคุมเอง |
| **Autonomous** | AI ของยาน ตามภารกิจที่ assign | **AI Core** (มี tier) | งานซ้ำ ๆ ขณะผู้เล่นทำอย่างอื่น |

- ยานหนึ่งลำรองรับได้หลายโหมด (มี Cockpit + AI Core = สลับได้) — ค่า `controlModes` **คำนวณจากชิ้นส่วนจริงบนยาน** ไม่เชื่อค่าจากไฟล์ที่แชร์ (สอดคล้องข้อ 10.3)
- **ยานสำเร็จรูปที่ซื้อ/prebuilt** มาพร้อมโหมดตามรุ่น (เช่น "Drone Harvester" = ไร้คนขับล้วน, "Scout Pod" = นั่งได้ 1 คน); ผู้เล่นปรับแต่งเพิ่ม/ถอด Cockpit หรือ AI Core ได้ใน builder
- **AI Core tiers** (ต่อยอดแนวคิด Autopilot ที่มีอยู่): Basic (บินไป-กลับ ตามจุด) → Advanced (เก็บ Scrap เป็นพื้นที่ หลบอุปสรรค) → Expert (ภารกิจหลายขั้น ตัดสินใจเอง กลับฐานเมื่อเสี่ยง)

**ภารกิจที่ assign ได้ (Mission board):**
| ภารกิจ | พารามิเตอร์ |
|---|---|
| Harvest sweep | พื้นที่/ชนิดทรัพยากร, เวลา |
| Survey / Scan | เป้าหมาย (ดาว/ซากยาน), ความละเอียด |
| Relic hunt | ระบุ sector/ทิศทาง (ถ้าเข้าถึงได้) |
| Courier | ขนของระหว่างยานแม่ ↔ สถานี |
| Patrol / Escort | จุด/เป้าหมายที่ดูแล |
| Return to base | ทันที |

ทุกภารกิจตั้ง **เงื่อนไขกลับฐาน** ได้ (เชื้อเพลิง/ความแข็งแรงต่ำกว่าเกณฑ์, ระยะสูงสุดจากยานแม่) และ **ระดับความเสี่ยง** (ระวัง/สมดุล/บุกเบิก)

**ข้อดีข้อเสียที่ทำให้เลือกจริง (ต่อ 8.3):**
- ไร้คนขับ: ถูก ไม่เสี่ยงชีวิต ไปนานได้ แต่ตัดสินใจจำกัดตาม AI tier และลงดาวยาก/สำรวจละเอียดไม่ได้
- มีคนขับ: ฉลาด ยืดหยุ่น ลงดาวและเจอเหตุการณ์พิเศษได้ แต่ใช้เวลาลูกเรือ + เสี่ยงต่อลูกเรือ (มีผลจริงเฉพาะ `lifeMode = full`)
- ทักษะลูกเรือยังมีผลกับยานไร้คนขับทางอ้อม: Engineer/ผู้ตั้งโปรแกรมที่เก่งเพิ่มประสิทธิภาพ AI *(ไอเดีย: Synth มีสายสัมพันธ์พิเศษกับโดรน — รอตัดสิน)*

**ฝูงยาน (Fleet):** ยานแม่มี Hangar slot จำกัด; แสดงรายการยานทุกลำพร้อมสถานะ/ภารกิจ/ตำแหน่ง ผู้เล่นสลับไปควบคุมลำไหนก็ได้ที่เป็น Manned/Remote

**ผลต่อสถาปัตยกรรม (ต้องรู้ก่อนทำ Phase B):**
- ใช้ **task controller ของ autopilot ที่มีอยู่ซ้ำ** (nav/harvest/hold/dock/...) เป็นฐานของ AI Core — แต่ต้องแยกให้ทำงานกับ "ยานใดก็ได้" ไม่ผูกกับ singleton (งาน Phase B เดิม)
- **ยานที่ผู้เล่นไม่ได้มอง** จะจำลองอย่างไร (ประเด็นสำคัญ ยังไม่ตัดสิน):
  - (ก) ฟิสิกส์เต็มทุกลำ — แม่นยำ แต่แพงมาก ไม่สเกล
  - (ข) ฟิสิกส์เต็มเฉพาะยานที่ active/อยู่ใกล้ยานที่ active, ลำอื่นจำลอง **แบบนามธรรม** (ตัวจับเวลาภารกิจ + ผลลัพธ์ที่คำนวณจากสถิติ/สุ่ม) — **ผมแนะนำ (ข)** แล้วค่อยเปลี่ยนเป็นฟิสิกส์เมื่อผู้เล่นสลับไปดู
- ข้อมูล: `ShipBlueprint.control = { seats, aiCoreTier?, remoteLink? }` (คำนวณซ้ำฝั่งผู้รับ), `ShipInstance.mission?`, `ShipInstance.pilotId?`

## 7. Data Model (ฐานของทั้งเซฟ, prebuilt, share และ trade)

> ทุก schema มี `schemaVersion` และ migration ได้ — หัวใจที่ทำให้ online ในอนาคตเป็นไปได้

```ts
// Blueprint = แบบที่แชร์ได้ (ไม่มีสถานะรัน)
type ShipBlueprint = {
  schemaVersion: number
  id: string                 // content-hash ของเนื้อหา (กันซ้ำ/ตรวจแก้ไข)
  kind: 'mothership' | 'scout'
  name: string
  authorId?: string          // เว้นว่างได้ตอน offline
  speciesTheme?: SpeciesId   // ธีมที่เหมาะ (ไม่บังคับ)
  hull: { cells: HullCell[] }                     // กริดโครง
  rooms: Room[]                                   // พื้นที่/ชนิดห้อง
  furniture: { itemId: string; pos: Vec3; rot: number; color?: string }[]
  exterior: PartPlacement[]
  stats: DerivedStats        // คำนวณได้ ไม่เชื่อค่าจากภายนอก (ดูข้อ 10)
  tags: string[]
}

type CrewBlueprint = {          // "ตัวละครที่แชร์/ส่งออกได้" (ไม่รวมสถานะเกม)
  schemaVersion: number
  name: string; species: SpeciesId
  appearance: { slot: string; partId: string; color?: string }[]
  traits: string[]; likes: string[]; dislikes: string[]
}

// Instance = ของจริงในเซฟ
type ShipInstance = { blueprintId: string; damage: ...; fuel: number; crewIds: string[]; ... }
type CrewInstance = {
  blueprint: CrewBlueprint; needs: ...; mood: ...; relations: ...; skills: ...
  genome?: Genome; parents?: [CrewId, CrewId]; generation: number   // ใช้เมื่อ lifeMode = 'full' (3.6.1)
  lifeStage?: 'baby' | 'child' | 'teen' | 'adult' | 'elder'; rearing?: RearingPlan  // (3.6.2)
}
type SaveGame     = { schemaVersion; ships: ShipInstance[]; crew: CrewInstance[]; inventory; progress: {...} }
```

กฎ: **Catalog ไอเท็ม (เฟอร์นิเจอร์/ชิ้นส่วน) อ้างด้วย `itemId` เท่านั้น** ห้ามฝังพฤติกรรมในไฟล์ที่แชร์ (กัน exploit/โค้ดแปลกปลอม)

## 8.1 แรงตึงเครียด vs ความอบอุ่น (Gameplay tension)

ลูกเรือที่ดูแลตัวเองได้ดีจะลบปัญหาเล็กทิ้งไปเอง → **ปัญหาใหญ่ต้องเป็นเรื่องที่ผู้เล่นแก้** ไม่เช่นนั้นเกมนิ่ง

- **ทรัพยากรจำกัด:** อาหาร, พลังงาน, ออกซิเจน, ชิ้นส่วนซ่อม ไม่ไหลฟรี — ผู้เล่นต้องเก็บ/ผลิต/ตัดสินใจจัดสรร
- **เหตุการณ์สุ่ม** (ความถี่และความแรงปรับตามความคืบหน้า): พายุสุริยะ, ท่อ/ระบบรั่ว, ไฟฟ้าดับบางส่วน, สัญญาณขอความช่วยเหลือ, ลูกเรือทะเลาะ/เศร้าเพราะเหตุการณ์ (ใช้กับ moodlets)
- **เป้าหมายระยะกลาง:** "ขยายยานให้รับคนเพิ่ม", "ปลดล็อกห้องใหม่", "ให้ลูกเรือทุกคนมี mood > X" — ให้ผู้เล่นมีอะไรไล่ตามระหว่างทางไป Earth 2.0
- **การตัดสินใจที่มีราคา:** ใช้ Scrap สร้างห้องนั่งเล่น (mood) หรือเครื่องยนต์ใหม่ (เดินทางไกลขึ้น)? ส่ง Scout ออกไปเสี่ยง หรืออยู่เก็บเสบียง?
- **หลักการ:** เหตุการณ์ต้อง "แก้ได้ด้วยทักษะ/การวางแผน" ไม่ใช่สุ่มลงโทษ; ลูกเรือตอบสนองเบื้องต้นเอง แต่การตัดสินใจเชิงกลยุทธ์เป็นของผู้เล่น

หลักการ: เป้าหมายต้อง **มาจากสิ่งที่ผู้เล่นทำอยู่แล้ว** (บิน สำรวจ ดูแลลูกเรือ ต่อยาน) ไม่ใช่ checklist ที่บังคับเล่นแบบอื่น; ทุกเป้าหมายมีรางวัลที่ใช้ได้จริง; Earth 2.0 ไม่เคยบังคับ

## 8.2 UI อ่านสถานะลูกเรือ (Readability)

- **Crew bar:** แถบด้านข้างแสดงรูปหน้า, ไอคอนอารมณ์, need ที่ต่ำสุด และกิจกรรมปัจจุบันของแต่ละคน
- **ไอคอนเหนือหัวตัวละคร:** อารมณ์/ความต้องการเร่งด่วนเมื่อซูมเข้าใกล้
- **Overlay ห้อง:** โหมดแสดงสี (เขียว/เหลือง/แดง) ตามคุณภาพของห้อง/ปัญหา เพื่อหาห้องที่มีปัญหาในพริบตา
- **สรุปปัญหา:** รายการสั้นแบบรวมกลุ่ม ("ขาดเตียง 1", "อาหารเหลือ 2 วัน") คลิกแล้วกล้องพาไปที่ต้นเหตุ
- **คลิกตัวละคร:** เห็น needs, mood, traits, ความสัมพันธ์ และ "กำลังทำอะไร ทำไม" (3.4.1)
- เกณฑ์: ผู้เล่นใหม่ต้องบอกได้ภายใน 5 วินาทีว่าทีมกำลังมีปัญหาอะไร (ทดสอบกับคนจริงใน Phase 0)

## 8.3 เหตุผลของยานสำรวจ (Why Scout exists)

ต้องมีสิ่งที่ **มีแต่ Scout ทำได้** ไม่เช่นนั้นจะถูกมองข้าม:
- ยานแม่ **ใหญ่เกินกว่าจะลงดาวได้/เข้าเขตแรงโน้มถ่วงสูงได้ปลอดภัย** → ลงดาวและเข้าบรรยากาศด้วย Scout
- Relic และ Scrap บางชนิดอยู่ใน **เขตที่ยานใหญ่เข้าไม่ได้** (ซากยาน, วงแหวนหิน, ถ้ำลึก)
- ยานแม่ **ประหยัดเชื้อเพลิงเมื่อจอด** ส่วน Scout ออกไปหาของแล้วกลับมา
- ลูกเรือบางคน (Pilot) มี skill เฉพาะที่ทำให้ Scout เก่งขึ้น → เป็นเหตุผลให้ใส่ใจการเลือกคนขับ
- ความเสี่ยงของ Scout (ไกลเกินพิสัย = ต้องกู้ภัย) ต้องเป็น **การตัดสินใจ ไม่ใช่การลงโทษ**

## 8.4 Open World — จักรวาลไม่จำกัดจำนวนกาแล็กซี

**ตัดสินใจแล้ว:** โลกเปิด มีกาแล็กซีได้ไม่จำกัดจำนวน

> **สภาพปัจจุบันของโค้ด (ตรวจแล้ว):** Space-Fold สร้าง sector ใหม่จาก **seed สุ่มทุกครั้ง** (`Math.random()` ใน `fold.ts`) และนับ `nextSectorId` ไปเรื่อย ๆ — จึงยัง **ไม่มีพิกัด** กลับไป sector เดิมไม่ได้ และไม่ใช่ "จักรวาลที่คงอยู่" การเปลี่ยนเป็นจักรวาลที่ระบุตำแหน่งได้และคงอยู่ เป็น **การ refactor ของระบบ fold/sector/save** ไม่ใช่แค่เพิ่มเนื้อหา

### ก. "ไม่จำกัด" ในทางปฏิบัติ
ไม่มีอะไรไม่จำกัดจริงในคอมพิวเตอร์ แต่ทำให้ **ไม่มีเพดานที่ผู้เล่นเดินชน** ได้ด้วย:
- **ผู้เล่นไม่ต้องเก็บจักรวาลทั้งหมด:** กาแล็กซี/sector ถูก *คำนวณจาก seed เมื่อถึงเท่านั้น* (generate on demand) ไม่มีการเก็บล่วงหน้า
- **พิกัดเป็นจำนวนเต็มขนาดใหญ่** (เช่นคู่/สามจำนวนเต็ม 64 บิตหรือ BigInt) + **hash 64 บิต** (เช่น splitmix/cyrb53) แทน `Math.random` → เลขนับเกือบไม่มีวันหมด
- **Floating-point precision:** ใช้ *พิกัดท้องถิ่นของ sector* (ที่ทำอยู่แล้ว — แต่ละ sector มีจุดกำเนิดของตัวเอง) ห้ามใช้พิกัดจักรวาลเป็น float ในฉาก 3D
- **ขนาดเซฟโตตามที่เคยไป ไม่ใช่ตามขนาดจักรวาล** (ดูหัวข้อ ง)

### ข. โครงสร้างลำดับชั้น
`Universe (universeSeed)` → `Galaxy (พิกัดจำนวนเต็ม)` → `Sector/ระบบดาว (พิกัดในกาแล็กซี)` → `ดาว/สถานี/จุดสนใจ`

- `seed(sector) = hash64(universeSeed, galaxyCoords, sectorCoords, generatorVersion)` — **พิกัดเดียวกัน = ที่เดิมเสมอ** (ย้อนกลับมาได้, แชร์พิกัดให้เพื่อนได้)
- **Galaxy Profile** (สุ่มจาก seed ของกาแล็กซี) กำหนด "นิสัย" ของกาแล็กซี เพื่อให้แต่ละที่ต่างกันจริง ไม่ใช่แค่เลขต่างกัน:
  ประเภท (กังหัน/แคระ/ทรงรี/ซากปรักหักพัง/หมอกหนา), ความหนาแน่นดาว, ความอุดมสมบูรณ์ของทรัพยากร, ความถี่ภัย (อุกกาบาต/พายุ), ความถี่สถานี/ตลาด, สีสัน/nebula, ความหายากของ Relic, พูล allele/ลูกเรือที่พบ (เชื่อม DNA 3.6.1 — ท้องถิ่นมีลักษณะเฉพาะ *ไอเดีย*)
- **Preview ราคาถูก:** ดูข้อมูลสรุปของ sector (ชื่อ, ประเภท, ระดับภัย) จาก hash ได้โดย *ไม่ต้องสร้างฉากเต็ม* → แสดงบนแผนที่ดาวได้เร็ว

### ค. การเดินทางและแผนที่
| ชั้น | วิธีไป | ต้นทุน |
|---|---|---|
| Sector ↔ Sector (ในกาแล็กซี) | **Space-Fold** เดิม (J) แต่เลือกปลายทางได้ | ราคา (HC/เชื้อเพลิง) **เพิ่มตามระยะ** |
| กาแล็กซี ↔ กาแล็กซี | **Intergalactic Drive** (ชิ้นส่วน/อัปเกรดแยก, ต้องไฟ/เชื้อเพลิงมาก, ใช้เวลาชาร์จนาน) | แพงมาก ต้องเตรียมตัว |
| กลับบ้าน | **Home Anchor** (จุดยึดที่ตั้งไว้ที่ drydock/สถานี ใช้ fold กลับได้) | ราคาปานกลาง |

- **แผนที่ดาว (Star Map):** ระดับ Universe/Galaxy/Sector, *fog of war* (เห็นเฉพาะที่ไปแล้ว/สแกนแล้ว), ปักหมุด/ตั้งชื่อ, บันทึกพิกัด; **Scout/โดรนช่วยเปิดแผนที่** (เชื่อม 5.1)
- ยานที่ไม่ได้ **เก็บใน Hangar ก่อน fold จะถูกทิ้งไว้ที่ sector เดิม** (กู้ทีหลังหรือเสีย) → ผู้เล่นต้องเรียกยานสำรวจกลับก่อนกระโดด *ผลโดยตรงต่อดีไซน์ฝูงยาน 5.1*

### ง. ความคงอยู่ (Persistence) — เก็บเฉพาะ "ส่วนต่าง"
- Sector ถูกสร้างใหม่จาก seed ทุกครั้งที่ไป แล้ว **ซ้อน delta ของผู้เล่น**: Scrap ที่เก็บแล้ว, Relic ที่เอาไปแล้ว, สิ่งที่ค้นพบ, ยานที่ทิ้งไว้, สิ่งก่อสร้าง/สถานีที่ผู้เล่นตั้ง (ถ้ามี)
- เซฟเก็บ `visited: { [sectorKey]: SectorDelta }` — โตตามที่ไป ไม่ใช่ตามจักรวาล
- **การรีเจนทรัพยากร:** Scrap กลับมาช้า ๆ เมื่อเวลาผ่านไป (กัน sector เก่า "ตายถาวร") และตัดแต่ง delta เก่าที่กลับเป็นปกติแล้วเพื่อคุมขนาดเซฟ
- **`generatorVersion` ต้องนิ่ง:** ถ้าแก้อัลกอริทึมสร้าง sector ภายหลัง พิกัดเดิมจะกลายเป็นที่อื่นและ delta พัง → เก็บ generator เวอร์ชันเก่าไว้ใช้กับเซฟเก่า หรือมี migration
- ผู้เล่นต่างคนที่ใช้ `universeSeed` เดียวกัน เห็นจักรวาลเดียวกัน (พร้อมสำหรับ Phase H ถ้าจัดโครงสร้างตามนี้)

### จ. ทำให้ "ไม่จำกัด" ไม่น่าเบื่อ
จำนวนไม่จำกัด ไม่เท่ากับความน่าสนใจไม่จำกัด:
- **จุดสนใจ (Points of Interest) แบบประกอบจากแม่แบบ:** ซากยาน, ความผิดปกติในอวกาศ, สถานีการค้า/อู่ต่อยาน, รังภัย, ซากอารยธรรม, ยักษ์ใหญ่ (megastructure) — แต่ละแบบมีหลายตัวแปร และมี *ระดับความหายาก* ควบคุมความถี่
- **Landmark ของกาแล็กซี:** กาแล็กซีหนึ่งมีไม่กี่จุดเด่นที่น่าไปให้ได้ (กำหนดจาก seed) เพื่อให้มีเป้าหมายระยะกลางในการสำรวจ
- **รางวัลการสำรวจ:** สมุดบันทึกการค้นพบ (Codex), ขายข้อมูลสำรวจที่สถานี, ปลดล็อกชิ้นส่วน/เฟอร์นิเจอร์ใหม่จากการค้นพบ
- **ความสมดุลของเศรษฐกิจ:** ทรัพยากรไม่จำกัดจะทำลายความขาดแคลน → คุมด้วยต้นทุนเดินทาง/เชื้อเพลิง/ไฟ (4.5), ความอุดมสมบูรณ์ต่อกาแล็กซี, การหมดแบบรีเจนช้า

### ฉ. เป้าหมายของเกมเมื่อจักรวาลไม่จำกัด — **ตัดสินใจแล้ว: ดูหัวข้อ 8.6** (ไม่มี victory จบเกม, Earth 2.0 เป็น easter egg; ตัวเลือก ก/ข/ค ด้านล่างเป็นเนื้อหาเดิมที่ถูกแทนที่แล้ว)
ตอนนี้ **ชนะ = ลงจอด Earth 2.0 แล้วจบ** (เก็บ 5 Relics) ซึ่งขัดกับโลกเปิดไม่จำกัดและระบบครอบครัว/รุ่นลูกหลาน ตัวเลือก:
- **(ก) แนะนำ:** ลงจอด Earth 2.0 = *จบ "เนื้อเรื่องหลัก" พร้อมฉากส่งท้าย* แล้ว **เล่นต่อได้อิสระ** (Sandbox) และอาณานิคมที่ตั้งเป็นฐานถาวร/ปลายทางของครอบครัว
- (ข) มี "Earth" หลายดวงในหลายกาแล็กซี แต่ละดวงเงื่อนไข/ผลลัพธ์ต่างกัน
- (ค) ตัด victory ออก เป็น sandbox ล้วน

### ช. ผลต่อสถาปัตยกรรมและเฟส
- เพิ่ม `universeSeed`, ตำแหน่งปัจจุบัน (`galaxyCoords`, `sectorCoords`) และ `visited` delta ลง **schema เซฟตั้งแต่ Phase A** (เหมือน `lifeMode`)
- แก้ `fold.ts`/`sector.ts`: `sectorAt(coords)` แบบ deterministic แทน seed สุ่ม; ระบบ Fold รับปลายทาง; ปรับ Earth sector ให้เป็น "จุดหมายที่รู้พิกัดหลังถอดรหัส" แทนการเปลี่ยน sector ถัดไปเป็น Earth ทันที
- **เฟสใหม่ Phase U (Universe)** ต่อจาก B (ดูรายการในหัวข้อ 8)
- Test: *determinism* (พิกัดเดิม → ฉากเดิมเหมือนทุกค่า), *delta round-trip*, *fuzz* สร้าง sector จากพิกัดสุ่มหลายหมื่นแห่งต้องไม่พัง/ไม่ว่างเปล่า/เวลาสร้างอยู่ในงบ

## 8.5 Space-Fold Spec

ต่อยอดจากโลกเปิด (8.4) — Space-Fold คือกลไกที่ผู้เล่นใช้บ่อยที่สุดในการเดินทาง จึงต้องมีน้ำหนักและความเสี่ยงที่ตัดสินใจได้ ไม่ใช่ปุ่มกดแล้วเสียเงิน

### ก. สถานะปัจจุบันของโค้ด (ตรวจเมื่อ 2026-10-04, `fold.ts` / `sector.ts` / `Ship.tsx`)
> **อัปเดต:** ตารางนี้เป็นสถานะ *ก่อน* งานเล็กบน branch `feature/fold-spec` — ที่ทำแล้วคือ ยกเลิกได้, ขัดจังหวะได้, ห้ามชาร์จในหลุมลึก/บรรยากาศ, EVAC ไม่ spam, จุดมาถึงมีตัวตรวจ; ค่าธรรมเนียมยัง **หักตอนเริ่มชาร์จ** แล้วคืนเมื่อยกเลิก (ไม่ใช่ "จองแล้วหักตอนกระโดด" ตามข้อเสนอเดิม — ผลทางเศรษฐกิจเท่ากัน ง่ายกว่าและทดสอบแล้ว)
| หัวข้อ | ปัจจุบัน |
|---|---|
| เริ่มกระโดด | `J` ในโหมด Pilot; ต้องไม่ได้จอด dock; ใช้ไม่ได้หลังชนะ |
| ราคา | `getFoldCost()` = 40 HC ปรับตามระดับความยาก (×0.8 / ×1 / ×1.25) หักตั้งแต่เริ่มชาร์จ |

| EVAC | Autopilot task EVAC สั่ง fold เองเมื่อ Hull ต่ำหรืออุกกาบาตพุ่งเข้า (ไม่มีราคาพิเศษ) |

**ยังไม่ได้ตรวจ:** Relic ที่อยู่ใน cargo (`cargo.relics`) กับตัวนับ `relics` ที่ใช้ปลดล็อก Earth เกี่ยวข้องกันอย่างไร เช่น ขาย/ทิ้ง Relic แล้วนับต่อไหม → ต้องตรวจก่อนแก้เงื่อนไข Earth

### ข. ข้อเสนอ — ชิ้นส่วน Fold Drive
Fold กลายเป็น **ชิ้นส่วนบนยาน (Fold Core)** มี tier อัปเกรด (เหมือน Harvester/AI):

| พารามิเตอร์ | ผลของ tier สูง |
|---|---|
| ระยะสูงสุดต่อครั้ง | ไกลขึ้น (ข้ามหลาย sector ในครั้งเดียว) |
| เวลาชาร์จ | สั้นลง |
| ความแม่นยำจุดมาถึง | เบี่ยงเบนน้อยลง |
| การใช้พลังงานขณะชาร์จ | อาจสูงขึ้นหรือประหยัดขึ้นตามดีไซน์ (เชื่อม 4.5) |
| Intergalactic | tier สูงสุดปลดล็อกการข้ามกาแล็กซี (8.4) |

### ค. ข้อเสนอ — เงื่อนไขและการชาร์จ
- **ห้ามชาร์จในหลุมแรงโน้มถ่วงลึกหรือในบรรยากาศ** (ใช้ `CELESTIAL_BODIES`/`wellRadius` ที่มีอยู่แล้วตรวจ) — ต้องออกห่างก่อน → ทำให้การบินสำคัญก่อนกระโดด
- **ต้องมีพลังงานพอ** (เมื่อระบบไฟ 4.5 พร้อม); ไฟไม่พอ = ชาร์จช้าหรือไม่ได้ ไม่ใช่ล้มเหลวเงียบ ๆ
- **ยกเลิกได้ระหว่างชาร์จ:** *จอง* ค่าใช้จ่ายตอนเริ่ม แล้วหักจริงตอนกระโดดสำเร็จ; ถ้ายกเลิก/ถูกขัดจังหวะ คืนส่วนใหญ่ (เสียค่าชาร์จบางส่วน)
- **ถูกขัดจังหวะได้:** Hull ลดต่ำกว่าเกณฑ์/ถูกชน/เข้าหลุมแรงโน้มถ่วงระหว่างชาร์จ → ยกเลิกอัตโนมัติพร้อมแจ้งเหตุผล
- **เงื่อนไขก่อนกระโดด** แสดงเป็นเช็กลิสต์บน HUD (เขียว/แดง): ออกนอกหลุม · ไฟพอ · เงินพอ · ยานสำรวจเข้า Hangar แล้วหรือยัง · cargo ปลอดภัย

### ง. ข้อเสนอ — ปลายทางและการมาถึง
- เลือกปลายทางจากแผนที่ดาว (8.4); ราคา/เวลาชาร์จขึ้นกับระยะ
- **จุดมาถึง:** มีความเบี่ยงเบนตาม tier (สูงสุดแบบ "ลงใกล้ดาว/สถานี/สิ่งกีดขวาง") แต่ **ไม่ทับกับวัตถุแข็ง และไม่อยู่ใต้พื้นผิวดาว/ในบรรยากาศลึก** (ตรวจตอนสร้างจุดมาถึง)
- ความเร็วตอนมาถึง: เริ่มต้นเป็น 0 เหมือนปัจจุบัน (เรียบง่าย ปลอดภัย); *ตัวเลือกภายหลัง:* tier ต่ำคงโมเมนตัมบางส่วนเพื่อความท้าทาย
- **Earth 2.0:** เมื่อ Relic ครบ ปลายทาง Earth **ปรากฏบนแผนที่ดาวเป็นพิกัดที่ถอดรหัสแล้ว** — ผู้เล่นเลือกเวลาไปเอง ไม่ใช่ fold ครั้งถัดไปถูกบังคับ (เชื่อม U1 ใน 8.4)

### จ. ข้อเสนอ — ผลต่อระบบอื่น
| ระบบ | ผล |
|---|---|
| ยานสำรวจ (5.1) | ลำที่ไม่อยู่ใน Hangar ถูกทิ้งไว้ที่ sector เดิม; เช็กลิสต์ก่อนกระโดดเตือน |
| ลูกเรือ | moodlet เบา ๆ ตอนกระโดด (ตื่นเต้น/เวียนหัวตาม trait/เผ่า) ในโหมด `full` ถ้าละเลยอาจมีผลต่อสุขภาพเล็กน้อย — ใน `npc` ไม่มีผลถาวร |
| Cargo | ไม่หายตอน fold (ตรวจเงื่อนไข Relic ตามข้อ ก) |
| ราคา/ความยาก | ใช้ `adjustedCost` ที่มีอยู่ต่อ (ไม่ทำระบบราคาซ้ำ) |
| Autopilot EVAC | ดู **Emergency Fold** ด้านล่าง |
| ระบบไฟ/AI (4.5) | Fold กินไฟ; AI ระดับสูงช่วยวางแผนเส้นทาง/คำนวณราคา |

### ฉ. Emergency Fold (EVAC)
ปัจจุบัน EVAC สั่ง fold หนีฟรีเมื่อ Hull ต่ำ — ทำให้ไม่มีน้ำหนักการตัดสินใจ ข้อเสนอ:
- **Emergency Fold** ชาร์จเร็วกว่ามาก **แต่แพงกว่า** และ **เสี่ยง**: ปลายทางสุ่มใกล้ (ไม่เลือกเอง), จุดมาถึงเบี่ยงเบนมาก, Hull เสียหายเล็กน้อยจากแรงกระโดด
- Autopilot EVAC ใช้ได้ **เฉพาะเมื่อมีเงินและเงื่อนไขพอ** ไม่เช่นนั้นแจ้งผู้เล่นแทนที่จะ fold ไม่สำเร็จเงียบ ๆ
- ห้ามใช้ Emergency Fold เป็นวิธีหนีหนี้/เลี่ยงภารกิจโดยไม่มีราคา

### ช. UX
วงแหวน/แถบชาร์จ + เช็กลิสต์เงื่อนไข + ตัวเลขราคา/เวลา + พรีวิวปลายทาง (ชื่อ/ประเภท/ระดับภัยจาก preview ของ 8.4) + แอนิเมชันมาถึงที่บอกชัดว่าเบี่ยงเบนแค่ไหน

### ซ. การทดสอบ
1. **การคงอยู่ของเงิน:** ไม่ว่าจะสำเร็จ/ยกเลิก/ถูกขัดจังหวะ เงินตรงตามกฎ ไม่เสียซ้ำ ไม่ได้เงินเปล่า
2. **ไม่มีสถานะค้าง:** fold กลางการ dock/ระหว่าง arrival state/ขณะชน/ขณะถูกขัดจังหวะ ไม่ทำให้ `fold.phase` ค้าง
3. **จุดมาถึงปลอดภัย:** สุ่มหลายหมื่นครั้ง ไม่เคยอยู่ในวัตถุแข็ง/ใต้พื้นผิว/ในบรรยากาศลึก
4. **Determinism:** พิกัดเดียวกัน tier เดียวกัน seed ของการกระโดดเดียวกัน → จุดมาถึงเดิม (สำหรับทดสอบ/replay)
5. **EVAC:** เงื่อนไขไม่พอแล้ว autopilot ไม่ spam คำสั่ง fold
6. **ยานสำรวจ:** ลำที่ถูกทิ้งไว้ถูกบันทึกลง delta ของ sector และกู้ได้เมื่อกลับไป

### ฌ. ลำดับงาน
- **งานเล็กทำก่อน Phase U ได้ (ไม่ต้องรอระบบอื่น):** เช็กลิสต์เงื่อนไข, ห้ามชาร์จในหลุมแรงโน้มถ่วง, ยกเลิก/คืนเงิน, ตรวจจุดมาถึงปลอดภัย, EVAC ไม่ spam
- **ใน Phase U:** เลือกปลายทาง, ราคาตามระยะ, Fold Core tiers, Earth เป็นพิกัดที่เลือกเอง, Emergency Fold
- **หลัง D2:** กินไฟ/AI ช่วยวางแผน

## 8.6 Earth 2.0 — Easter Egg และ Relic Map

**ตัดสินใจแล้ว (ปรับจาก 8.4 ฉ):**
- **Relic = ชิ้นส่วนแผนที่ไปยัง Earth 2.0**
- **Earth 2.0 เป็น easter egg** ไม่ใช่เป้าหมายบังคับ และ **ไม่มี victory ที่จบเกม** — เกมเป็น sandbox ต่อเนื่อง
- การไปถึง Earth 2.0 ให้ **ปลดล็อกหรือได้ของที่ดีมาก** (ข้อ ค — ข้อเสนอของผม ยังไม่ผ่านการยืนยัน)

> **ผลต่อโค้ดปัจจุบัน:** `gameStats.victory` ตอนนี้เป็นสถานะสิ้นสุด (ปิดการใช้ `P`/`J`/`R` ผ่าน `unavailableAfterVictory` ใน `keymap.ts`, มี VictoryOverlay, `RELICS_NEEDED = 5`, `earthSector` ถูกเข้าโดย fold ครั้งถัดไปทันที) ทั้งหมดต้องเปลี่ยนเป็น **เหตุการณ์ปลดล็อกที่ไม่ล็อกเกม**

### ก. Relic = แผนที่ (Relic Map)
แนวคิด: Relic ไม่ใช่ "ตัวนับ 5 ชิ้นแล้วจบ" แต่เป็น **ชิ้นส่วนแผนที่ที่ค่อย ๆ ชี้ทางไป Earth 2.0**

| จำนวนชิ้นส่วน | สิ่งที่รู้ |
|---|---|
| 1 | ทิศทางคร่าว ๆ / บอกว่า "มีอะไรบางอย่างอยู่ไกลมาก" (ข้อความลึกลับ ไม่เด่น) |
| 2–3 | บีบพื้นที่เหลือระดับกลุ่มกาแล็กซี/กาแล็กซี |
| 4 | ระบุกาแล็กซีและบริเวณที่อยู่ |
| ครบ | **พิกัด sector ของ Earth 2.0** ปรากฏบนแผนที่ดาว (8.4) เป็นจุดหมายที่เลือกไปเอง |

- **ตำแหน่ง Earth 2.0 ผูกกับ `universeSeed`:** `hash(universeSeed, "earth-2.0")` → จุดคงที่ของจักรวาลนั้น (ผู้เล่นคนละเซฟมีที่ต่างกัน; เพื่อนที่ใช้ seed เดียวกันเจอที่เดียวกัน — สอดคล้อง 8.4)
- **ไกลพอจะต้องเตรียมตัว:** วางอยู่ห่างจากบ้านเกินระยะ fold ปกติ ต้อง **Intergalactic Drive** (8.5) → ประตูความก้าวหน้าตามธรรมชาติ ไม่ต้องล็อกด้วยกฎ
- **ชิ้นส่วนแผนที่ไม่ใช่ cargo:** เก็บใน **Map Case / Codex** (ไม่กินความจุ ขายไม่ได้ ทิ้งไม่ได้ ไม่หายตอน fold) — แก้ความกำกวมของ `cargo.relics` กับ `relics` ที่ตรวจพบใน 8.5 ข้อ ก; โค้ดปัจจุบันนับ Relic เป็น cargo ต้องเปลี่ยน
- **ตำแหน่งของชิ้นส่วนแต่ละชิ้น** (ข้อเสนอ):
  - **(ก) แนะนำ — โซ่ของเบาะแส:** แต่ละชิ้น *ชี้พื้นที่ของชิ้นถัดไป* ได้ภารกิจสำรวจที่มีทิศทาง ไม่ใช่สุ่มเดินเอง; ชิ้นแรกซ่อนอยู่ใน Landmark ใกล้บ้าน (ค้นเจอได้ด้วยการสำรวจปกติ)
  - (ข) กระจายสุ่มตามความหายากใน POI/Landmark ทั่วไป แล้วผู้เล่นปะติดปะต่อเอง
  - ทั้งสองแบบกำหนดจาก `universeSeed` (deterministic)
- **ความลับ:** ไม่แสดง "Relic 0/5" เด่นบน HUD เหมือนตอนนี้ — ปรากฏเฉพาะใน Codex หลังเจอชิ้นแรก และมีข้อความสั้น ๆ ครั้งเดียวตอนเจอ ("สัญญาณจางๆ ที่ไม่ใช่ของใคร...") เพื่อให้เป็น easter egg จริง ผู้เล่นที่ไม่ตามก็เล่นเกมต่อได้ไม่เสียอะไร
- (ทางเลือกเสริม) **ข่าวลือ (Rumors)** จากสถานี/NPC ให้เบาะแสเพิ่ม ลดโอกาสที่ไม่มีใครเจอ

### ข. การไปถึง Earth 2.0
- ยังต้อง **ลงจอดนุ่มนวลสำเร็จ** (≤ 12 u/s, ระบบ arrival/landing ที่มีอยู่) จึงจะปลดล็อก — การบินยังเป็นทักษะ ไม่ใช่ผ่านเฉย ๆ (เดิมนี่คือ victory; เปลี่ยนเป็นจุดปลดล็อก)
- Earth sector ยังเป็นระบบสงบ (ไม่มีภัยหนัก) และมีฉาก/เสียง/ภาพพิเศษตอนมาถึงและตอนแตะพื้น
- **ไม่จบเกม:** หลังแตะพื้นเล่นต่อได้ทันที `gameStats.victory` ถูกแทนด้วย flag เช่น `earthDiscovered` ที่ไม่ปิดฟังก์ชันใด ๆ
- ผลของการไปถึงบันทึกในเซฟ และ (ข้อเสนอ ค.3) อาจเป็นมรดกข้ามเซฟ

### ค. รางวัล — ข้อเสนอ (ผู้เล่นได้ "ของดีมาก" โดยไม่ทำให้เกมเสียสมดุล)
หลักการ: **ดีมากในแง่ความรู้สึก/สถานะ/ความสะดวก/เอกลักษณ์ ไม่ใช่ปุ่มโกงทรัพยากร** (เช่น ไม่แจก HC ไม่จำกัด) เพราะเป็น sandbox ไม่จำกัด ถ้าได้พลังมหาศาลเกมที่เหลือจะหมดความท้าทาย

**แนะนำเป็น 4 ชั้นรวมกัน:**

1. **ความจริงของ Earth (Lore reveal):** ข้อความ/ภาพ/บันทึกจากชาว Earth เดิม เล่าที่มาของ Relics และของยานตัวเอง — ราคาถูก กินใจ และเป็นรางวัลที่ "ไม่ทำลายเกม" (Codex หมวดพิเศษ)
2. **Earth Haven — บ้านหลังแท้ (ฐานถาวร):**
   - ท่าเรือที่ **ปลอดภัยที่สุดในจักรวาล**: ซ่อมยานฟรี, บริการ drydock เต็มรูปแบบ, Gene Counselor ฟรี, เติมพลังงาน/เสบียงในราคาต่ำ
   - **ลูกเรือทุก need เต็มเมื่ออยู่ที่นั่ง** (พักใจ) — จุดพักผ่อนจริง ๆ ของครอบครัวที่ผ่านการเดินทางมานาน
   - **ใช้กับระบบ Life Mode:** เป็นที่ **ฝากเลี้ยงเด็ก/เกษียณ** ที่ดีที่สุด (ตัวเลือกใหม่ในการเลี้ยง 3.6.2), ที่ตั้ง **อนุสรณ์ของบรรพบุรุษ** ถาวร, ที่ทายาทกลับมา
   - **Home Anchor ฟรีถาวร** (8.4) — fold กลับ Earth Haven ได้ทุกเมื่อ (ยังต้องมีค่า fold ปกติ)
3. **มรดก/ของเอกลักษณ์ (ไม่ใช่พลังทำลายสมดุล):**
   - **"Ark" — hull/รุ่นยานเฉพาะ** (blueprint ชุดตกแต่งพิเศษ + ห้องพิเศษ) เน้นรูปลักษณ์และความสะดวก เช่น ช่องห้องสวนใหญ่
   - **เฟอร์นิเจอร์/ตกแต่ง/ชุด Earth** ใช้แต่งยานและตัวละคร
   - **Earth heritage genes:** allele หายากที่ปรากฏในลูกหลาน (เช่น ลักษณะ/ความทนทานเล็กน้อย) — เชื่อม DNA 3.6.1 เป็นเรื่องเล่ามากกว่าพลัง
   - สิ่งเหล่านี้ **แชร์/ซื้อขายไม่ได้** (ปลดล็อกส่วนตัว ตามกฎ 10.3 ข้อ 5/5b) เพื่อรักษาความพิเศษ
4. **มรดกข้ามเซฟ (ตัวเลือก — ตัดสินใจทีหลัง):** การไปถึง Earth ในเซฟหนึ่งปลดล็อกของเล็ก ๆ ในเซฟใหม่ (ลายพิเศษ/ตัวเลือกเริ่มต้น/ข้อความ) ทำให้เกมน่าเล่นซ้ำโดยไม่ทำลายสมดุล

**ทางเลือกที่พิจารณาแล้วไม่แนะนำ:**
- *รางวัลเป็นพลังโกง/เงินมหาศาล* — ทำลายสมดุลและความตึงเครียดของ sandbox ไม่จำกัด
- *จบเกมพร้อมเครดิต* — ขัดกับโลกเปิดและระบบหลายรุ่น และขัดกับ easter egg (คนที่หาไม่เจอจะรู้สึกว่าเกมไม่จบ)
- *ล็อกฟีเจอร์หลักไว้หลัง Earth* — easter egg ต้องไม่บังคับ

### ง. ผลต่อเอกสาร/ระบบอื่น
- **8.4 ฉ / U1:** ตัดสินใจแล้ว ตัวเลือกเดิมถูกแทนที่ด้วยหัวข้อนี้
- **8.5 ง:** Earth เป็นพิกัดที่ถอดรหัสได้ → ใช้แผนที่ดาวตามข้างบน (ตรงกันอยู่แล้ว)
- **Phase U/C2/F:** Earth Haven เป็นเนื้อหาของ Phase U (ปลายทาง) + ตัวเลือกเลี้ยงเด็ก (C2) + Ark (F)
- **GAME_DESIGN.md:** ส่วน "เป้าหมาย/ชนะ" และเนื้อเรื่อง (Earth 2.0 = เป้าหมายสุดท้าย) ต้องปรับเมื่อลงมือทำจริง (ดูหมายเหตุที่หัวเอกสารนั้น)
- **เป้าหมายระยะยาวของผู้เล่น** แทนที่จะเป็น "ไป Earth" คือ: สร้างบ้าน/ครอบครัว/ฝูงยาน สำรวจจักรวาล และ (ถ้าสนใจ) ตามหา Earth — ต้องแน่ใจว่า 8.1 (แรงตึงเครียด/เป้าหมายระยะกลาง) ทำงานจริง เพราะไม่มี victory คอยดึง

### จ. การทดสอบ
1. Earth 2.0 อยู่ที่เดิมสำหรับ `universeSeed` เดิม (determinism) และต่างกันระหว่าง seed
2. ทุกชิ้นส่วนแผนที่หาเจอได้จริง (ไม่อยู่ในที่เข้าไม่ได้); โซ่เบาะแสไม่ตัน
3. ชิ้นส่วนแผนที่ไม่หายตอน fold/ขาย/โหลดเซฟ
4. หลังแตะ Earth เกมเล่นต่อได้เต็มรูป: ไม่มีปุ่มถูกปิด, state ไม่ค้าง
5. รางวัลทุกอย่างปลดล็อกครั้งเดียว ไม่ซ้ำ ไม่ติดเมื่อโหลดเซฟ
6. รางวัล Earth Haven ใช้งานได้ทั้ง `npc` และ `full`

### ฉ. ข้อกำหนดที่ล็อกแล้ว (ผมตัดสินให้ ปรับตัวเลขได้ตอน balance)

## 8.7 Station 2.0 — สถานีอวกาศ

**สรุป:** แผนก่อนหน้านี้ใช้สถานีเป็น "ที่ตั้งของบริการ" (Crew Hall, Gene Counselor, Contracts, Station Daycare, Marketplace, Earth Haven) แต่ **ยังไม่มีแผนยกระดับตัวสถานีเอง** (รูปลักษณ์ โครงสร้าง ความหลากหลาย) — หัวข้อนี้เติมส่วนนั้น และตัดสินว่าจะทำ **แยกเป็นแทร็กของตัวเอง แต่ผูกเข้ากับเฟสหลัก** ไม่รวมเป็นเฟสเดียว

### ก. สถานะปัจจุบัน (ตรวจจาก `SpaceStation.tsx` / `station.ts`)
- สถานี = **โมดูลอู่ต่อยานเดี่ยว**: ช่อง hangar ขนาด 18×14×30, วงแหวนรอบ (torus), แกนกลางทรงกระบอก, แขนกล, ไฟทางลง/ไฟสัญญาณ; มีแค่ drydock (สร้าง/แก้ยานเมื่อ dock)
- มีสถานีเดียวที่บ้าน (`Haven Drydock`) และสถานีสุ่มบาง sector ผ่าน `makeStations`; **ทุกแห่งหน้าตาและหน้าที่เหมือนกัน**
- เหตุที่ "ยังไม่เหมือนสถานีอวกาศ": เป็นอู่ลอยฟ้า ไม่มีส่วนที่อยู่อาศัย/ตลาด/ท่าเรือหลายช่อง/ยานสัญจร/ป้าย/ชีวิตภายใน

### ข. ทำไมไม่รวมเป็นเฟสเดียว
- **บริการ (gameplay)** เป็นสิ่งที่เฟสอื่นต้องพึ่ง (Contracts ใน Phase 0, Crew Hall ใน G, Daycare ใน C2, Marketplace ใน H) → ต้องออกแบบเป็น **ชั้นบริการแบบ data-driven** ก่อน
- **รูปลักษณ์/โครงสร้าง (visual)** เป็นงานศิลป์ก้อนใหญ่ ไม่ควรขวางงาน gameplay → ทำคู่ Phase E
- **ความหลากหลายของสถานี** ผูกกับจักรวาล (8.4) → ทำคู่ Phase U
- **ภายในที่เดินได้** ใหญ่มาก → ตัวเลือกท้ายสุด

### ค. ชั้นบริการของสถานี (Station Services) — data-driven
สถานีแต่ละแห่งประกาศ `services: ServiceId[]` ตามประเภท; UI สถานีเป็น **เมนูบริการ** (ไม่ต้องรอฉากภายใน):

|---|---|---|

| Trade / Sell | ขาย cargo (Scrap/Survey Data) เป็น HC (มีแล้วที่ drydock + Relay) | มีแล้ว |
| **Contracts Board** | สัญญาระยะสั้น | **Phase 0** |
| Crew Hall | จ้าง/รับลูกเรือ, พี่เลี้ยง | G / C |
| Medical Bay + Gene Counselor | รักษา, ที่ปรึกษาพันธุกรรม | C2 |
| Station Daycare / Adoption | ฝากเลี้ยง, ครอบครัวอุปถัมภ์ | C2 |

### จ. Station Visual 2.0 (ทำคู่ Phase E)
- **โครงสร้างแบบโมดูลประกอบ:** วงแหวนที่อยู่อาศัยหมุนช้า (มีหน้าต่างเรืองแสง), แกนกลาง, ท่าเทียบ (docking ports) หลายช่อง, แผงโซลาร์, เสาอากาศ/จาน, โมดูลเฉพาะประเภท (โดมแล็บ, ถังเชื้อเพลิง, ตลาด)
- **ชีวิตรอบสถานี:** ยานสัญจร NPC ขึ้นลง, แสงไฟ/ป้าย/โฮโลแกรม, เสียงบรรยากาศ (เชื่อมงานเสียง)
- **สไตล์:** คงภาษาภาพของเกม (HDR emissive + bloom, วัสดุเรียบแบบ clay/toon ถ้าเหมาะ) — *ต้องทดสอบว่าเข้ากับสถานีขนาดใหญ่*
- **ประสิทธิภาพ:** instancing ชิ้นซ้ำ (หน้าต่าง/ไฟ), LOD ตามระยะ — สถานีใหญ่ต้องไม่ฉุด FPS (งบ performance ตามข้อ 9)
- **ไม่ทำลายระบบ dock เดิม:** ตำแหน่ง/ทิศของ hangar, `SLOT_LOCAL`, `ENTRANCE_LOCAL`, เส้นทาง Bezier ต้องคงอยู่หรือแปลงผ่านข้อมูลเดียว — แก้ทีเดียวที่ `station.ts`

### ฉ. โครงสร้างด้านจอดยาน (ผูกกับฝูงยาน 5.1)
- สถานีมี **ช่องจอดหลายช่อง** (drydock bay เฉพาะยานแม่ + ท่าเทียบเล็กสำหรับยานสำรวจ/ยานอื่น)
- ยานสำรวจที่ค้างอยู่ที่สถานีกู้ได้ทีหลัง; ยานแม่ที่จอดแล้วถูกตรึง (กฎเดิม `mass = 0`)

### ช. ภายในที่เดินได้ (Station Interior) — *ตัวเลือก ตัดสินใจทีหลัง*
เดินในสถานีเหมือนเดินในยาน (concourse/ตลาด/Crew Hall) เพิ่มชีวิตชีวามาก **แต่ใหญ่** (ต้องมีฉากภายใน, NPC, pathfinding, UI ผูกกับสถานที่) — ตอนนี้ให้ใช้ **เมนูบริการ + ภาพพื้นหลัง/ภาพนิ่งของสถานที่** เป็นขั้นต้น และเก็บการเดินได้ไว้เมื่อยานภายใน (Phase D) นิ่งแล้ว เพราะใช้ระบบห้อง/pathfinding ร่วมกันได้

### ซ. เฟสที่เสนอ (แทร็ก S)
- **S0 (ใน Phase 0):** โครงบริการ `services` + หน้าเมนูสถานี + Contracts Board
- **S1 (คู่ Phase E):** Station Visual 2.0 + ประเภทสถานีเบื้องต้น (Drydock Hub ขยาย + Trading Post) + ช่องจอดหลายช่อง
- **S2 (คู่ Phase U):** ประเภทสถานีครบ ตาม Galaxy Profile + Chart Office + Earth Haven
- **S3 (ตัวเลือก):** ภายในที่เดินได้

### ฌ. การทดสอบ
1. สถานีทุกประเภท/seed สร้างได้โดยไม่ทับกับดาว/อุกกาบาต (keep-out ยังทำงาน)
2. dock/undock ทำงานกับทุกประเภทและรูปแบบช่องจอด (ไม่ทะลุ/ไม่ค้าง)
3. `services` ที่ประกาศตรงกับที่ UI แสดงและทำงานได้
4. FPS ใกล้สถานีใหญ่ที่สุดอยู่ในงบ
5. สถานีเดียวกัน (พิกัดเดิม) หน้าตา/บริการเดิมเสมอ (determinism)

## 10. ออกแบบเผื่อ: Share & Trade ผ่าน Store ในสถานี (Phase H)

> **ยังไม่ implement** — เก็บไว้เป็นข้อกำหนดให้ Phase A–F ไม่ทำให้ทางนี้ตัน
> ขั้นแรกแบบบางที่ทดลองได้หลัง Phase A (อัปโหลด/ดาวน์โหลด blueprint อย่างเดียว ไม่มีซื้อขาย) ดู **Phase H0**

### 10.1 สิ่งที่แชร์/ซื้อขายได้
Ship blueprint (mothership/scout), crew blueprint (รูปลักษณ์+บุคลิก ไม่ใช่ความคืบหน้า), ชุดตกแต่ง/เฟอร์นิเจอร์ (คอลเลกชัน), (ภายหลัง) ลาย/สีพิเศษ

### 10.2 โหมดการแจกจ่าย
| โหมด | ความหมาย |
|---|---|
| **Share (ฟรี)** | เผยแพร่ใน Store ให้คนดาวน์โหลด/ใช้เป็นฐาน |
| **Gift** | ส่งให้เพื่อนโดยตรง |
| **Trade** | แลกเปลี่ยนกับผู้เล่นอื่น (ของ ↔ ของ / ของ ↔ สกุลเงินในเกม) |
| **Sell** | ตั้งราคาใน Store |

### 10.3 ข้อกำหนดที่ต้องรักษาตั้งแต่ตอนนี้
1. Blueprint **serialize ได้เต็มรูป มี `schemaVersion` และ `id` เป็น content-hash**
2. **ไม่ฝังโค้ด/พฤติกรรม** ในไฟล์ — อ้าง `itemId` ใน catalog กลางเท่านั้น (ป้องกัน exploit)
3. **ค่า `stats` คำนวณใหม่ฝั่งผู้รับเสมอ** ไม่เชื่อค่าในไฟล์ (กันโกง)
4. **Ownership/provenance:** `authorId` + ประวัติการเปลี่ยนมือ; ลอกแบบ (copy) กับถ่ายโอนกรรมสิทธิ์ (transfer) ต้องแยกจากกัน
5. **ห้ามซื้อขายสิ่งมีชีวิต:** ตัวละคร/เด็ก/ทายาท/genome ไม่เป็นสินค้า ไม่มีราคา ไม่มี trade ด้วยสกุลเงิน — แชร์ได้แค่ appearance blueprint (เห็นภาพ/ลักษณะ ไม่ใช่ตัวตนหรือสายเลือด); "ทายาท/ครอบครัวอุปถัมภ์" เป็น mechanic ภายในเกม ไม่ผ่าน Store
5b. **ไอเท็มที่ผู้เล่นปลดล็อกยากต้องไม่ถูกคัดลอกเลี่ยงได้** — ออกแบบ "blueprint ใช้ชิ้นส่วนที่ผู้รับยังไม่ปลดล็อก" ให้ทำงานได้ (ล็อกชิ้นส่วนนั้น/ต้องซื้อ/แทนด้วยชิ้นใกล้เคียง)
6. **Thumbnail/พรีวิว** สร้างได้จาก blueprint (render offscreen) เพื่อใช้แสดงหน้า Store
7. **ตรวจความถูกต้อง (validate)** ก่อนรับเข้าเกมทุกครั้ง: ขนาดสูงสุด, จำนวนชิ้น, itemId ที่รู้จัก

### 10.4 สถาปัตยกรรมออนไลน์ที่น่าจะต้องมี (ภายหลัง)
- Backend: บัญชีผู้ใช้, kv/DB เก็บ blueprint, API list/search/upload/download, ระบบ trade แบบ atomic (escrow)
- Moderation: รายงาน/ลบเนื้อหา, ตรวจชื่อ/ภาพที่ไม่เหมาะสม, rate limit
- Economy: สกุลเงินในเกมที่ผูกกับ Scrap หรือแยก, กันเงินเฟ้อ/ฟาร์มโกง
- **จุดตัดสินใจที่ยังเปิด:** ผู้เล่นไม่ล็อกอินจะดูของใน Store ได้ไหม · เซิร์ฟเวอร์ authoritative แค่ trade หรือรวมเซฟด้วย · เงินจริงเกี่ยวหรือไม่ (ส่งผลด้านกฎหมาย/ภาษี)

### 10.5 UI ใน Haven Drydock (ภายหลัง)
เคาน์เตอร์ "Marketplace" ในสถานี: แท็บ Browse / My Blueprints / Trade / Gifts พร้อมพรีวิว 3D และปุ่ม "ใช้เป็นฐานสร้าง"

**0 (Vertical slice) → A (Data/Save + ช่อง universe/lifeMode) → (H0 Thin Online ตัวเลือก) → B (Multi-ship) → U (Universe) → C (Crew AI) → C2 (Life Mode) → D (Interior) → D2 (Ship AI & Power) → E (Visual) → F (Scout/Prebuilt) → G → H**
